# 0004 领域模板加开放字段

Status: accepted
日期：2026-10-07

## 背景

事实字段的词汇写死在 `knowledge_context_fields.go`：`context_length`、`local_deployment`、`license`、`released_on`，以及关系 `developed_by`、`successor_of`。单位换算也只支持 tokens。
本项目需要覆盖多个领域，不同领域的对象类型、字段、单位都不同。

## 决策

- 新增"领域"概念，每个知识库属于一个领域。
- 领域模板定义对象类型、字段（别名、值类型、单位族、适用对象类型）、关系和抽取提示，可以在界面上编辑。
- 抽取时优先使用模板字段名；模板外的字段按来源原名保存为开放字段。
- 提供字段归并视图：管理员把高频的开放字段映射到模板字段（追加别名）或新建字段。映射只影响查询，不改写原始事实。
- 现有固定词汇作为"AI 行业"领域的初始模板。

考虑过的其他方案：严格 schema 只抽取模板字段，会漏信息；完全开放不做归一，结构化对比基本不可用。

## 后果

- 新领域不改代码，只需配置模板。
- 抽取提示词由模板动态生成，提示词质量取决于模板的维护质量。
- 开放字段会持续积累，需要定期归并，否则结构化查询的覆盖率会下降。
