# 0019 库专用规则只存本机：通用提示词、目录驱动归并、可选质量评分

Status: accepted
日期：2026-10-27
修订 [0018](0018-closed-entity-catalog.md)（品牌归并、质量评分）。

## 背景

参照 AIHOT 重构后，仓库里的默认提示词、质量评分画像、Go 代码中的模型品牌正则，以及首次启动导入的预置机构和领域，都是为一个 AI 资讯库写的。这些规则对其他库并不适用：质量评分对所有外部库生效，会把非 AI 主题的资料大量判为低分；目录外名称在匹配目录前就占满 3 个实体名额。用户也不希望某个库的专用规则出现在远程仓库中。

## 决策

- **仓库只保留通用规则。** 默认提示词不写具体品牌、行业或读者画像。某个库的专用规则写成库级提示词，保存在本机数据库，由前端编辑；备份随 `system_settings` 一起保存。
- **不预置目录内容。** 删除代码中的预置机构和预置领域，全新安装从空目录开始。已导入的数据库内容不受影响。
- **品牌归并由目录驱动。** 删除代码中的品牌正则。原文名称先按规范名或别名完全匹配；否则取作为前缀的最长目录名称，且剩余部分以非字母开头并含数字时归入该实体。同长度命中多个实体时不挂接。不含数字的型号写法需要加为别名。
- **先匹配目录，再取前 3 个。** 目录外名称不占用名额。
- **质量评分是库级开关，默认关闭。** 开关键为 `prompt.library.<库ID>.quality_scoring_enabled`，在提示词页的质量评分项中切换。生成的报告不评分。
- **每篇只评一次，低分删除。** 新资料评分两次，两次之和低于门槛时，删除资料并按丢弃来源记录原因，之后同一来源不再收录。重建不评分，重新处理沿用已有结果，避免重新抽样误删已通过的资料。批量“重新评分”操作删除。旧版本标为低分的资料在列表中保持隐藏，另行清理。
- **评分调用关闭思考。** 输出上限 512 token，分数允许小数并四舍五入。

## 后果

- 远程仓库不再包含库专用规则；历史提交中的内容仍然存在，不改写历史。
- 部署前需要先把专用提示词保存为对应库的库级提示词，并打开该库的质量评分开关，否则该库会改用通用规则且不评分。
- 低分删除不可逆：被删资料不进入回收站，只留下丢弃来源记录与操作日志。
- 品牌归并的准确度取决于目录与别名的维护；不含数字的型号名漏加别名时不会挂接。
