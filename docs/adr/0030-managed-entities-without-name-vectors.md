# 0030 受管实体库不做实体名称向量，恢复只等待必需的模型

Status: accepted
日期：2026-11-21

## 背景

实体名称向量来自抽取模式：文章中抽出的实体写法多样（如“宁德时代”“CATL”），先用名称向量召回相似的已有实体，再由模型判断是否为同一实体。受管实体库（[ADR 0021](0021-managed-entity-library.md)、产品货架 [ADR 0023](0023-product-shelf-structure.md)）沿用同一张实体表和实体服务，新建、修改、合并、拆分时也排了名称向量任务。

受管库的实体是预设的，身份按名称、别名、代码和识别键精确判断，含义不确定时交给人确认；`shelf_find` 用文字匹配，从不读名称向量。只有产品货架的部署中，698 个实体没有一个名称向量，却积压了上千个向量任务。型号名彼此高度相似（如同一型号的 IEC 与 UL 版本），向量“相似”对货架没有意义。

空间默认选中本机 Ollama 向量模型，`setup-models` 原先试调所有启用模型，任一失败即停在 `waiting_models`。没有任何需要向量的内容时，交付数据也必须先装 Ollama 和模型才能完成恢复。

## 决策

- 名称向量只用于 `entity_mode=extracted` 的库。受管库实体的写入不排名称向量任务，重建只处理抽取库实体，已排队的受管实体任务按无事可做完成；向量核对不要求受管实体有名称向量。
- 维护命令 `models` 输出 `embedding_required`：向量启用库中存在分块、已完成文章、可向量化图片，或抽取库存在实体时为真。
- `setup-models` 只因已选生成模型和必需的已选向量模型失败而等待；其他模型失败只报告受影响的功能。`embedding_required` 为假时，向量模型不可用不阻止恢复；向量模型身份变化且向量必需时才全部重建。

## 取舍与验证

被否决的方案：要求所有部署安装 Ollama，额外常驻服务和约 600MB 模型只为一个受管库不用的功能；清空空间的向量模型选择，`setup-models` 仍会试调启用中的内置模型，且会被当作换模型触发重建；为受管库保留名称向量做“疑似重复”提示，重复检测已由识别键和同名规则承担。

代价：受管库以后若需要语义相似查找，须另行设计，不能直接复用实体名称向量。抽取库的召回与重建行为不变。

验证：PG 测试覆盖受管实体写入不排任务、旧任务无模型时完成、全量重建跳过受管实体、向量缺口与恢复核对排除受管实体、`embedding_required` 的真假条件；脚本测试覆盖向量模型可选与必需时的等待状态。
