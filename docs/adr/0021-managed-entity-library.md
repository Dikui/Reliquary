# 0021 库级人工维护实体

Status: accepted
日期：2026-11-06
后续修订：[0022 产品库的关联与演进](0022-managed-catalog-evolution.md) 替代本文的同库关联、仅空库转换、当前值属性及不支持合并的限制。
修订：[0016 实体按库独立](0016-library-catalogs.md) 中所有库开放抽取的规则；库间隔离保持不变。

## 决策

在现有 Library 增加 `entity_mode` 与 `entity_schema`。默认 extracted；managed 库由网页或 HTTP 维护实体、属性和关系，文档处理只匹配已存在的活动实体。只允许空库切换模式。

复用 PostgreSQL 实体、关系、关联表与操作日志。人工实体保留 product 存储类型，以库内 kind 区分类别。属性使用按库校验的 JSON：文本、数值、布尔、日期、单选。已有数据引用的类别、字段、类型、单位和关系规则不能改成与数据冲突的定义；废弃字段可归档。

实体使用 revision，关系使用现有 version 检查并发更新。归档替代实体物理删除，保留历史关联。有活动子项时不能归档父项。层级关系在库内最多一种启用类型，方向为子项到父项，至多一个父项且禁止环。其他关系可多对多。

EntryEntity 增加 origin、excluded、evidence 和 body_hash。重处理保留人工关联与排除。普通读取忽略排除项，证据只对应哈希一致的原始正文。未知或多义名称不会自动创建实体。人工关系不需要文档来源，清理文档不会删除产品图谱。

Neo4j 继续作为异步只读副本。所有实体与关系修改在事务中写入原有待同步表。资料检索继续使用全文与向量融合、重排；可按需展开下级实体，并为最终命中附带父块上下文。

## 取舍与验证

不增加图数据库、权限体系或通用业务流程引擎，不保存旧正文版本。历史修改通过原有操作日志查询。沿用名称与别名唯一性，暂不支持人工实体合并。

验证库配置与实体编辑、属性校验、并发修订、层级环拒绝、归档恢复、人工关联保留、资料重建不改写图谱、下级检索与父块上下文，以及副本导出导入。迁移 37 仅增加默认字段；存在人工维护库时拒绝执行降级脚本，避免丢失产品数据。
