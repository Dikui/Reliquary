# 0017 接收故障只记日志，不保留故障包

Status: accepted
日期：2026-10-25

## 背景

外部 Agent 投递资料遇到技术故障（数据库、存储、队列等内部错误）时，系统曾在独立诊断目录保留故障包：原始条目、图片、执行条件和模型调用，保留 7 天、上限 512 MiB，并提供三组 HTTP/MCP 接口、前端“接收故障”页面和 `recovery_failure_id` 关联字段。

系统只有一个用户。外部采集层自己保留原文，排查时可以从来源重新抓取；为一种少见的失败维护独立存储、容量淘汰、接口和页面，成本高于收益。

## 决策

- 删除故障包存储、诊断目录配置（`ingest_diagnostics`、`RELIQUARY_DIAGNOSTICS_*`）、故障查询接口与 MCP 工具、前端页面，以及入库结果的 `diagnostics` 字段。
- 删除入库请求的 `recovery_failure_id`。入库接口仍拒绝未知字段，继续发送该字段的调用方会收到错误。
- 技术故障只在应用日志写一行：条目序号、库、来源 URL、标题、正文字数、图片数和错误原因。不保存正文和图片。
- 明确拒绝、参数错误和认证失败照旧只返回错误。

## 后果

- 排查只能依据日志和调用方保留的原文，无法再还原“当时那一份”输入。
- 接收失败期间的模型调用与成功时一样写入调用记录，不再只留统计。
- 已有部署中的 `logs/diagnostics` 目录和 `.env` 的 `RELIQUARY_DIAGNOSTICS_DIR` 不再使用，由用户自行删除；恢复旧迁移包时仍会剔除该变量。
