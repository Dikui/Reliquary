# 0003 单团队空间，删除多租户与共享

Status: accepted
日期：2026-10-07

## 背景

上游是多租户平台，包含组织、共享空间、跨租户共享知识库和智能体、租户切换、平台级 API Key、Embed 外链等功能。
本项目由 2–10 人的小组在一台服务器上使用，不对外提供服务，也不再合并 WeKnora 上游改动。

## 决策

- 系统内只有一个租户，即团队空间。注册和邀请都加入这个租户。
- 删除组织、共享空间、跨租户共享、租户切换、Embed 外链及相关界面和文档。
- 保留租户角色 owner / admin / contributor / viewer。owner 是团队创建者，owner / admin 对应管理员，contributor 对应编辑者，viewer 对应只读者。团队成员都能查看全部知识库。
- 知识库都属于团队：不提供个人知识库，也不提供指定成员可见的知识库。
- 登录方式为账号密码加邀请注册，删除 OIDC。
- 数据库中的 `tenant_id` 列和索引保留，值固定。逐表删除这一列的改动面太大，收益很小。

## 后果

- 检索、问答、Agent 不再处理跨租户的来源投影，权限判断简化为角色加知识库范围。
- 安全面缩小。不合并上游以后，保留模块（沙箱、MCP、OAuth、文件下载、SSRF 防护）的安全修复要自己跟进：关注 WeKnora 的安全公告，涉及保留模块时手动移植。
- 以后如果需要对外提供服务或多团队隔离，需要重新引入租户隔离。
