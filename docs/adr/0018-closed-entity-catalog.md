# 0018 实体封闭目录：删除待确认实体、候选审核与实体图谱

Status: accepted
日期：2026-10-27
部分取代 [0016](0016-store-and-track-event-layer.md)（待确认实体、候选审核、实体图谱）、[0014](0014-internal-knowledge-base.md)（开放实体抽取、图谱副本与图谱检索）。沿用 [0002](0002-global-entity-registry.md) 的全局统一身份，去掉自动建档路径。

## 背景

实体层经过多轮收敛后仍以“模型品牌、Agent、软件产品、具名技术和协议”为对象，资料理解会为目录外名称生成待确认实体。线上积累 150 条待确认记录、34 个正式实体，但审核入口基本无人使用；实体图谱只有一层邻居，实际使用率接近零。用户明确表示不想人工校验、图谱基本不用，希望把处理流程收敛到 AIHOT 已验证的“结构化 + 归组 + 质量过滤”。

## 决策

- **实体是封闭目录。** 实体只能由用户在实体页新增、编辑、合并或删除；资料理解、长文合并、事实端点只在传入的实体选项中按规范名或别名匹配。未匹配的名称不保存、不创建实体、不生成待确认项。
- **删除待确认实体。** 移除 `entity_candidates`、`entity_candidate_occurrences`、`entity_candidate_entries` 三张表，以及候选列表、详情、通过、并为别名、忽略接口与前端审核页。迁移 `000052_drop_entity_candidates` 执行删除；历史待确认数据（约 150 条）不迁移、不备份到新表。
- **删除实体图谱。** 移除 `GET /entities/:entity_id/graph`、图谱聚合服务与前端图谱面板。实体页只保留事实时间线（可按发生时间与分页）和涉及该实体的资料。
- **事实端点保持不变。** 事实仍可带可空的主体、对象实体 ID；ID 必须来自目录。事实端点文字按规范化 key 精确匹配目录，未匹配留空。在实体页新增别名后，仍对未挂接的历史端点精确回填一次。
- **品牌归并保持不变。** 模型品牌、Agent 或软件产品、具名技术的抽取与归并规则继续由 `article_processing` 提示词定义；本次只把“目录外保留待确认”改成“目录外不输出”。

## 后果

- 资料理解输出更短，目录外噪声不再进入数据库；实体页与侧栏少一个审核入口，图谱相关接口、类型、测试与会话状态删除。
- 迁移不可逆地删除候选表；降级只恢复表结构，不恢复候选数据。执行前如需保留候选内容，应单独导出。
- 提示词与代码必须同时升级：运行目录的 `config/prompt_templates/processing.yaml` 需同步，否则旧提示词仍会要求输出待确认名称；迁移 `000052` 需走显式升级流程。
- 领域、资料、事实、事件链路不变；质量评分与归组不受影响。

## 相关

- 质量评分（两次独立打分、低分隐藏）见 `config/prompt_templates/processing.yaml` 的 `quality_scoring` 模板与 `quality_scoring.go`。
- 归组与事件层仍依据 ADR 0016。
