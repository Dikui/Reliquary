# 0013 用户文档改为导入，不可修改

Status: accepted
日期：2026-10-12
部分被 [0014](0014-internal-knowledge-base.md) 取代（2026-10-14）。
部分取代 [0009](0009-kb-collect-store-retrieve.md)（用户文档放 `mine/`，程序只读并监听变化建索引）

## 背景

[0009](0009-kb-collect-store-retrieve.md) 让用户在 `mine/` 中直接编辑文档，程序监听文件变化、停止变化一段时间后按变化分块重建索引，不调用模型、不写表头。这要求维护监听、去抖等待与增量重算，数据库也不保存这些文档的原文，磁盘损坏时只能依靠备份。用户文档同时不能按实体、主题筛选。

[0012](0012-ingest-only-no-collection.md) 之后，内容统一经收录接口进入。用户希望自己的文档也以同样方式进入。

## 决策

- 用户文档通过收录接口导入（HTTP 与 MCP 的收录条目标记为本人文档），与外部内容经过相同步骤：去重、收录审核、处理调用（内容类型、摘要、实体、主题）。审核未通过时进入收录待审，由用户决定。
- 两处例外：用户文档一律全文保存，不因内容类型只存摘要；不要求原始链接，不进入缺链接待审。
- 导入后程序写入 `mine/`，带表头，正文不可修改。要修改时删除后重新导入。网页、接口与 MCP 提供删除，不提供编辑。
- 取消对 `mine/` 的监听与增量重建。用户在 Obsidian 中直接修改 `mine/` 的文件不会被识别，以数据库和表头为准。
- 待审区的“转为本人文档”改为走同一导入路径。
- 整理结果（`reports/`，经 `write_report` 写入）不审核、不处理，只建索引。

## 后果

- 用户文档可以按实体、主题筛选，并与文章使用相同的检索与折叠规则；与文章之间不做转载归并。
- 每篇用户文档导入时多一次审核和一次处理调用。
- 数据库保存用户文档正文，可以从数据库补回 `mine/` 文件；只靠文件库也能按表头重建。
- 用户不能在 Obsidian 中边写边更新索引；写作在别处完成后再导入。
