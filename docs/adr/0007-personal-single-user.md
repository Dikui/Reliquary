# 0007 改为个人单用户使用

Status: accepted
日期：2026-10-08

## 背景

[0001](0001-postgres-only.md) 和 [0003](0003-single-team-space.md) 的前提是 2–10 人小组在一台服务器上使用。
现在确定由一个人自己使用。按团队设计保留下来的角色、邀请、API Key 作用域、审计日志，以及多个客户端入口和外围功能，维护和测试成本远大于收益。
P0 删除了多余的数据库和检索后端，但为多后端切换保留的中间层还在。

## 决策

- 只有一个用户。第一个注册的用户是唯一用户，之后关闭注册；不再有成员、邀请和角色区分，登录后拥有全部权限。
- 保留 API Key，只有完全访问一种，删除检索 / 入库 / 完整三种范围和按证据可见性过滤对象的逻辑。
- 删除审计日志、密码策略、管理员重置密码。提供本地命令重置密码。
- 只保留 Web 界面一个入口：删除 CLI、Go client、Python MCP server、飞书 IM。数据源只保留 RSS 和站点适配器。
- 完成 P0 的单后端收尾：检索直接查询 PostgreSQL，删除检索引擎注册表、按向量库分组的并发检索和向量库配置；文件只存本地文件系统；文档解析保留内置转换器和 MinerU；Redis 只保留任务队列。
- 删除全部联网搜索（问答联网、Agent 搜索工具、工作流网页研究步骤）。主动调研以后重新开发，见 `.scratch/web-research/issues/01-active-research.md`。抓取指定网址和按网址收录保留。
- 删除 Wiki、Agent 长期记忆及历史对话搜索、RAG 评测、沙箱和技能。工作流只保留知识搜索、事实查询、生成报告三种步骤。
- `tenant_id` 列继续保留，值固定，理由同 0003。

## 后果

- 0003 中的角色、邀请注册和团队 API Key 范围不再适用；0006 中受限 API Key 的可见性规则随之失效。单租户和全部知识库可见的结论不变。
- 安全面明显缩小：没有代码执行、没有第三方 IM 和外部数据源凭据、没有多用户越权问题。
- 找回新来源只能靠 RSS、站点适配器、手动网址和上传。
- 如果以后要多人使用，需要重新引入角色和权限，并重新评估本决策。
