# 0012 Reliquary 不负责采集，只提供收录接口

Status: accepted
日期：2026-10-12
部分被 [0014](0014-internal-knowledge-base.md) 取代（2026-10-14）。
部分取代 [0009](0009-kb-collect-store-retrieve.md)

## 背景

[0009](0009-kb-collect-store-retrieve.md) 保留了 RSS 订阅、站点适配器、网页导入网址与上传文件。讨论信源接入时发现：

- 没有订阅地址的官网、推特、公众号、视频各需不同的抓取方式，站点适配器随网站改版失效，10 个适配器中已有 3 个无法取到正文。
- 推特等需要登录的来源，基于账号 cookie 的抓取工具违反平台条款并有封号风险；官方方式（xAI API、Grok）属于外部服务。
- 外部 Agent（Grok Bot 等）读取网页、推文、文件的能力更强，也更容易随来源变化调整。

讨论过程见 `.scratch/kb-reshape/spec.md` 第三轮。

## 决策

### 职责边界

- Reliquary 后端不负责采集、订阅和信源追踪，也不发出任何对外内容请求：不抓原文、不下载图片和文件。
- 前端阅读时保留原网站图片的显示，由浏览器直接加载正文中的远程资源，不经过后端下载或代理。浏览器显示不替代收录材料补全，也不改变缺失清单。
- 订阅、手动收集、调研都由外部工具完成，通过收录接口送入。外部工具的选择、信源名单、采集频率不在本项目范围内，本项目也不为外部工具编写配置或 skill。
- 收录之后的去重、收录审核、处理调用、文件库写入、检索保持不变。
- 网页上的手动入口（导入网址、上传文件）删除，留待以后自建前端时再做。

### 完整材料优先

接口对外明确：送入的应是完整材料，即正文全文、原始文件、图片文件。能送文件就送文件；拿不到时才送链接，并写明原因。

- 正文缺失（只有链接）：不能处理，进入收录待审，原因为“正文缺失”。补入全文后按正常流程审核。
- 正文齐全、文件或图片缺失：正常入库并可检索，标记为待补全，记录缺失项与外部工具给出的原因。

### 补全

- 外部工具从 `list_incomplete` 读取缺失清单，重新获取后用同一原文链接再次收录。Reliquary 识别为补全，只补缺失项，不改动已有内容；补齐后去掉标记并重新执行处理调用。
- 外部工具补全一次后仍有缺失，该文章不再出现在 `list_incomplete`，只留给用户处理，避免反复重试。
- 补全时送来的正文与原正文明显不同，不覆盖；新内容作为一条关联原文章的收录待审，由用户决定另存为新文章或丢弃。
- 用户可接受缺失，文章保持现状并去掉标记。
- Reliquary 不主动联系外部工具。外部工具通过收录返回结果和 `list_incomplete` 得知缺失；用户通过网页的待处理页面得知。

### 正文定稿

- 正文在补全完成或用户接受缺失后定稿，之后不再改动。
- 定稿前只允许把图片引用替换为本地文件、补入文件链接，正文文字不变，由程序核对。

### 待处理页面

收录待审、处理待复核、待补全三个标签放在同一个待处理页面，导航栏显示合计数量。

## 后果

- 删除 RSS 连接器、站点适配器、调度器、订阅源配置与同步日志、网页导入网址与上传文件、按链接下载图片。现有订阅源在删表前导出为文件保存。
- 收录接口不再访问内容来源网站，SSRF 防护只在仍有对外请求的地方保留（如模型服务调用）。模型、embedding 和解析服务调用保留；浏览器阅读时可直接加载原网站图片。
- 没有外部工具时，Reliquary 无法自行获得新内容；外部工具停止工作时，Reliquary 不会察觉。
- RSS 改由外部工具负责后，可能需要 Agent 调用（消耗模型额度）或另装现成工具。
- 用户在电脑上手动收录一篇文章也需要经过外部工具，直到自建前端提供手动入口。
- 外部工具送入的内容可能经过改写，获取方式字段（逐字原文、网页提取、模型整理）用于标识，模型整理的内容在待审区与检索结果中标记。
