# 0006 结构化数据按关注范围生成

Status: superseded
被 [0009](0009-kb-collect-store-retrieve.md) 取代
日期：2026-10-08

## 背景

知识数据分层 issue 02 对 50 条公开材料的统计显示，每条消息平均产生 4.7 条事实、1.16 个事件、3.52 个可回溯对象关联。AI 行业与开源软件领域的模板外字段分别占全部事实的约 99% 与 97%。目前没有事实查询或引用的使用记录，无法证明全量开放字段抽取的收益。统计及其样本局限见 `.scratch/knowledge-data-layering/evidence/02/report.md` 第 3 节。

领域模板当前覆盖率很低，全量抽取会持续增加开放字段归并和事件维护负担。用户决定先实施收录时的最小方案，按单人使用场景考虑，权限沿用现有规则。本决策限定 [0004](0004-domain-templates-open-fields.md) 的开放字段抽取范围，字段归并与原始事实语义保持不变。

## 决策

- 每条符合现有收录条件的消息都保存不可变证据快照，识别对象并保存消息证据与对象的关联。对象解析继续使用 P3 的召回加判断。
- 关注范围是星标对象、星标具体所指标签（主题）以及已启用跟踪任务涉及的对象与主题的并集。星标使用独立数据结构，不复用知识库、智能体等资源收藏。
- 在对象识别和解析后，以消息的对象及具体所指标签判定是否命中关注范围。命中的消息完整抽取模板字段、开放字段与事件；范围外消息仅保留领域模板字段事实，包括模板定义的关系及字段别名，不产生开放字段事实或事件。
- 跟踪范围从启用工作流的 `fact_query` 对象条件推导，包括对象跟踪模板中的对象名称，以及 `entity_id`、`object_entity_id`、`entity` 条件。按步骤的知识库、领域或团队范围解释条件。自由查询文字不推断为主题或对象身份；当前工作流没有结构化主题条件，主题跟踪集合暂为空。
- 范围外消息不增加模型调用。第一轮使用精简提示词，每段只要求对象和模板字段或关系事实，不要求开放字段或事件；服务端保留过滤作为防御。分段始终按原完整提示词所需窗口规划，范围内外共用相同分段。
- 命中后每段追加一次补缺抽取，只要求开放字段事实与事件，不重复输出对象或模板事实。第一轮对象、别名及模板事实直接复用，第二轮端点引用必须对应第一轮已验证的提及，引文仍须来自当前段。保留原完整抽取的引文、日期、事件和汇总材料语义，不改变 P3 对象与事件解析算法。调用记录沿用 P3。
- 证据的 `extraction_mode` 使用 `template_only` 或 `full`，与分段覆盖状态、已处理分段数及总分段数分别记录。工作台展示模式，结构化查询提示按对象关联统计的相关模板抽取消息数。本次不提供补抽入口。
- 加星标不自动重抽历史消息，取消星标不删除已有事实或事件。

## 后果

- 关注范围以外的消息不再产生事件，事件时间线与热度只覆盖收录时命中关注范围的消息；已有事件继续保留，不能把时间线当作全库变化的完整统计。
- 按模板当前约 1% 至 3% 的覆盖率，范围外消息几乎不产生事实。仍可通过全量原文、证据和对象关联检索这些消息；模板维护会影响以后的抽取产出。
- 令 S 为实际尝试的分段数，U 为对象判断次数，E 为事件判断次数，A 为关注价值评分次数，B 为名称向量调用次数。改动前调用预算为 S + U + E + A + B；范围外为 S + U + A + B；范围内为 2S + U + E + A + B。第二轮不再增加对象判断。范围外的提示词和输出结构更少；范围内两轮合计只输出一次对象、模板事实、开放事实和事件，但会读取两次正文并承担两次请求开销，不能仅凭调用次数宣称总 token 成本降低。实际规模以替身记录及真实模型用量评估。
- 模式记录只说明抽取的结构范围，不保证模型识别完备，也不代替 P3 的分段覆盖信息；相关模板抽取消息计数不证明这些消息满足尚未抽取的字段或数值条件。
- 按需补抽、字段级覆盖与补抽入口属于以后评估的完整方案。触发条件包括用户需要对范围外消息进行结构化比较、历史事件分析，或关注范围扩大后需要回补历史材料。届时需明确重试、去重、模板版本和覆盖语义，继续绑定不可变证据，不把分析结论保存为事实。
