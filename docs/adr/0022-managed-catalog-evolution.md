# 0022 产品库的关联与演进

Status: accepted
日期：2026-11-06
修订：[0021 库级人工维护实体](0021-managed-entity-library.md)。

## 决策

产品实体仍归属一个人工维护库；文献可以放在同一空间内的其他库。文献库通过 `product_library_ids` 选择自动匹配的产品库，普通库继续抽取自己的实体。自动关联只接受正文中的唯一名称、代码或别名，不改写产品资料。全部名称合成标准库正则并启用 `Longest()`，收集符合词边界的重叠位置，只丢弃被其他命中完全包含的名称；歧义或关闭的长名称仍抑制被其完全包含的短名称。边界无效的长名称不抑制有效短名称。匹配器按目标产品库 ID 与持久化更新时间缓存，产品编辑、归档、重组和转换均刷新时间戳。查询与编译在缓存互斥锁外执行。人工维护库的模型提示词要求 entities 与 relations 为空，产品关联只由正文匹配完成。正文证据位置批量计算，自动关联替换与清理处于同一身份锁事务。

实体的 `auto_match` 保存名称、代码和别名的显式开关；键按现有实体名称规则规范化。不设开关时，两字以内的纯中文名及两位以内的纯字母数字代码默认关闭，其余开启。已有名称也采用此默认值；开启短名称代表接受其出现在更长词中的字面匹配，本方案不做中文分词。改名保留旧名及其开关，移除别名时移除对应开关；合并继承来源开关，目标的显式选择优先。手工关联不受开关影响，已有自动关联在重新处理后更新。手工关联不要求先配置自动匹配。

文献与产品的关联增加 `relation_type`。产品库用 `document_relation_types` 配置可选类型，默认包括涉及、规格书、测试报告和对比评测。自动关联使用 `references`；其他类型由人工指定。每个文献与产品组合保留一个类型以及原有排除决定。重新处理不覆盖人工决定。

产品关系增加 JSON 属性。每个关系类型用 `fields` 定义自己的字段。产品与关系共用字段校验，支持文本、数字、布尔、日期、单选、多选、文本列表、产品引用、HTTP(S) 链接和附件。产品引用按同一空间校验，附件引用还须属于同一库；附件复用文件存储与资源登记，单文件最多 32 MiB。历史仍可引用的附件不会因清空当前字段而删除。未被当前或历史属性、关系引用的附件允许删除，编辑取消时清理本次上传的无引用附件。产品引用字段保持单值，多产品联系使用关系表达。

`entity_attribute_versions` 保存完整属性快照、业务生效时间和记录时间。按指定时间选择最新已生效快照，同一生效时间取较大修订号。未来快照到时生效，读取时计算。查询早于最早快照返回未知；完整快照会整体替代当时的属性。保存与该时刻相同的属性不新增快照；本次改变的字段同步到已有的未来快照，保留未来快照的其他字段。类别变更只验证当前属性，不用新类别重验历史快照。名称、类别与归档状态仍是当前状态。已有或历史数据使用的字段不能改成不兼容定义，可归档。

关系用 valid_from/valid_to 保存业务有效区间 `[valid_from, valid_to)`，查询默认返回当前关系，也可指定 as_of。新增、修改可指定 RFC 3339 的 valid_from，结束可指定 valid_to；省略时使用实际保存时刻，不允许未来时间或零时间。修改在新 valid_from 处结束旧记录；结束时间须晚于该记录的 valid_from，不能产生空区间或倒置区间。修改与迁移建立新关系，旧记录保留；created_at/updated_at 仍表示实际记录时间。三元组唯一索引仍只约束尚未结束的关系。层级约束按同一类型内的有效区间检查，包含已结束的历史记录，任意时刻同一子项至多一个父项且无环；首尾相接不算重叠，组成环的整条路径必须存在共同生效时刻。合并、拆分等结构调整仍立即执行。

合并在同库内进行：保留目标 ID，显式提供合并后的属性，迁移文献与关系，来源归档并记录目标。拆分保留原实体，创建新实体，仅迁移明确选择的文献关联，关系可明确选择迁移或复制。两者记录来源链，原有属性时间线留在原实体。来源的未来属性快照不自动转给目标。合并请求的 `drop_relation_ids` 可指定先舍弃哪些来源关系，以解决父项或重复边冲突；只接受该来源的关系 ID，删除前值写入操作日志。文献关联类型冲突可指定采用来源或目标的类型；相反的排除决定仍拒绝。未解决的重复关系、自环和非法层级会拒绝整个事务，已选择的删除也回滚。结构调整立即执行；请求中的生效时间仅作用于结果属性，不得为未来时间。

库可启用多种层级类型，单父项与无环约束在各类型内独立检查。无文献、关系或其他受保护引用的产品可删除；归档产品保留历史，但不占用活动名称。非空代码唯一性不区分大小写，归档不释放代码。

已有文献的库可以转换为人工维护。转换前展示数量，并要求将每种已有实体类型映射到一个库内类别。转换前跨原类型检查活动名称冲突并列出冲突项；人工维护名称唯一性不按原存储类型区分。实体 ID、原存储类型、文献和关系保留；已有文献关联转为人工决定，转换时为属性建立基线。新建的人工实体仍使用 product 存储类型。转换与入库写入共用锁，避免旧抽取任务继续改写产品目录。

## 持久化与验证

迁移 38 增加字段及属性历史、重组记录、附件登记表。迁移 39 增加 `entities.auto_match`，旧记录默认空开关表；开关随导出和恢复保留。旧人工实体最后保存的快照是最早已知状态，不反推更早状态。普通文献的归属不迁移。迁移 40 增加关系有效区间并更新活动关系、名称与代码索引；既有代码大小写冲突时拒绝升级并列出冲突，不自动删除或改名。新数据进入已有导出、恢复与校验流程；独立 Markdown 导出使用精确实体 ID 保存跨库关联，不能用名称猜测恢复。含新增业务数据时拒绝降级。

验证覆盖跨库且带类型的关联、自动匹配与人工排除保留、关系属性、五种新增字段、附件下载、已有库转换、属性时间查询、合并拆分的事务回滚，以及升级和导出恢复。
