# 0016 存储加跟踪：资料、事实、事件三层与预设实体

Status: accepted
日期：2026-10-24
部分取代 [0009](0009-kb-collect-store-retrieve.md)（不建事实与事件、删除领域）、[0014](0014-internal-knowledge-base.md)（知识图谱、关系与关系类型、Neo4j 副本、实体开放抽取与核查、内容类型与主题、关注动态、相似折叠、摘要要点）、[0002](0002-global-entity-registry.md)（自动建档与身份判断）
沿用 [0005](0005-event-layer-bounds.md) 的有限关联原则：关联只展开一层，不做传递推理。
设计过程：`.scratch/tasks/aihot-fusion/`（`synthesis.md`、`design-v2.md`）。

## 背景

Reliquary 要同时承担两件事：存下外部收集的原始资料和外部归纳结果，并从时效型资料中认出发生了什么、展示一件事的进展。现有的开放实体抽取和长期关系图谱噪声大、核查成本高，也回答不了"这件事后来怎样了"。AIHOT 已经验证了"报道 → 事实 → 事件"的归组流程，本决策把它移植进来，同时去掉新闻站专属的部分（热度、评分、编辑精选、事件综述生成）。EyeAndEar 只负责抓取、判重、修订去抖和正文抽取，不调模型。

## 决策

### 定位

- Reliquary = 存储 + 跟踪。归纳不在 Reliquary：外部 AI 经 MCP 读取，把结果作为 AI产出写回。
- 事件页只显示事实时间线，不生成综述。

### 名词

库、资料、事实、事件、实体、领域。代码名：资料 `Entry`、事实 `Fact`、事件 `Story`、实体 `Entity`、待确认实体 `EntityCandidate`。`Event` 与前端 DOM 类型冲突，不用；不设"名录"类型。

### 三层收敛

- 资料与事实之间只有一张关联表，角色为**出处**或**提及**。一篇资料最多当 1 个事实的出处，每次出处附一句逐字引文；一个事实可有多篇出处。综合稿、外部归纳结果（`cannot_be_fact`）只能提及事实。
- 每个事实恰好属于 1 个事件。事实字段：标题、主体、动作（自由文字）、对象、条件、发生时间、两端实体 ID（可选）、人工纠正标记、合并跳转。各来源的不同说法以引文保留，事实没有别称。
- 同一事件的标准：后一件事直接作用于前一件事（评测、回应、上架、调查、后续披露）。同一家公司、同一产品、时间相近都不够。
- 只有外部时效型库的资料产生事实。其他库只存储、检索。
- 资料修订或删除时立即撤除其出处证据。出处被撤光的事实隐藏但保留 ID，仍参与召回，修订后的资料大多能挂回原事实，事件 ID 与关注不变。

### 链路

抓取 → 入库（`source_id` 加单调修订号，旧修订不得覆盖新修订）→ 资料理解（含选实体）→ 程序校验 →（仅时效型库）召回 → 归组判定 → consolidate。

- 召回：按 `published_at` 或事实发生日期取 ±14 天内向量相似度 ≥0.6 的候选事实。无候选时直接新建事实与事件，不调模型。两个日期都没有时不设时间窗，只允许高置信的"同一次发生"挂到已有事实，不能发起事件。
- 归组判定（四种）：同一次发生 → 成为已有事实的出处；同一件事 → 在其事件下新建事实；无关 → 新建事实与事件（须有 `published_at`）；没有事实的资料只记提及。≥0.85 的判定复核。
- consolidate 合并重复事件；有 ≥2 篇独立资料桥接的事件建立相关事件。人工纠正优先于自动判定。

### 资料理解

- 所有库：中文标题、一句话概述、领域（0–3）、涉及的实体（0–3，只从已有实体选）。
- 时效型库另输出：事实框架加引文、事实两端（已有实体 ID，或标明机构 / 人物 / 其他）。
- 删除 scope、体裁、要点、关键名词、评分。提示词写明综合稿不输出事实。
- 程序核对引文逐字出现在原文、实体 ID 与领域来自给定选项，不合格字段丢弃。

### 实体

- 实体只有预设或人工通过两种来源，类型为机构、人物；产品与模型第一期不进实体，只存文字。跨库共用。
- 事实一端未匹配到实体、模型标为机构或人物时，程序按规范化 key（NFKC、去首尾空白、小写、去全部空白）归入待确认实体，并记录出现在哪个事实的哪一端。只有事实两端产生候选，署名作者不算；长效型等不产生事实的库不产生候选。
- 人工通过、并为别名或忽略。通过与并为别名时按出现记录直接挂 ID，不检索；忽略后仍追加出现记录。只有在实体页手动给已有实体加别名时，对历史事实端点做一次精确匹配回填。
- 别名只来自种子数据和人工操作，不由模型学习。不调模型做身份判断；同一 key 命中多个实体时不挂。

### 领域

- 领域挂在资料上（所有库，0–3 个），事件的领域 = 出处资料领域的并集（提及不算），不单独存储。
- 用途：资料列表与事件列表筛选，不做领域关注。初始只有 Agent、LLM（LLM 指大模型本身：架构、训练与后训练、推理能力、模型发布与评测，基于模型构建的应用不算）。
- 新增领域只对新资料生效；资料页可手动改；可手动触发对已有资料重判，跳过人工改过的资料。

### 用户维护的内容

领域、实体等凡由用户增加的内容，一律在前端增改并存入数据库，不靠配置文件加重新部署。种子数据只做首次导入。

### 跟踪与查看

- 以事件为跟踪单位。关注对象是事件和实体。关注动态 = 事件列表加筛选（关注的事件，或含有一端为关注实体的事实），按最近一次新事实的时间排序，卡片突出触发的事实；新增出处不算新事实。不推送，第一期不做已读状态。
- 事件列表与资料列表各有一个筛选框，可混选实体与领域；MCP 查询可带同样条件。
- 图谱：节点为实体，边为两端都是实体的事实，同一对实体按主体到对象的方向合并成一条边（显示最近动作和事实数，点开看时间线）。只展开一层，点邻居换中心，可按时间筛选。单端事实不画，点节点时在侧栏时间线显示。不单独存储。
- 实体页 = 涉及它的事实时间线（可按另一端筛选）+ 涉及它的资料。

### 删除

热度与评分；事件综述生成；体裁、内容类型、主题与历史归入；收录审核旧代码；资料自检三类；相似报道折叠；摘要要点与关键名词；开放实体抽取、实体身份判断模型与实体核查；关系、关系类型、关系抑制、图谱证据核查、Neo4j 图谱副本与 1–3 跳图谱检索；库设置中的关系类型清单与实体身份模型；按库"上次查看时间"的已读状态；旧数据兼容代码。

## 考虑过的方案

- **保留开放实体与长期关系图谱**：噪声和核查成本已在 0014 的多轮修订中显现，且关系只表达状态、没有时间和出处，回答不了进展。改为以事实为边。
- **领域、实体、体裁合成一种标签**：实体需要主体 / 对象位置，三者挂载对象不同（资料、事实端点），早期"具体所指标签 / 内容性质标签"已因此拆分后删除。只在界面上统一筛选入口。
- **领域挂在事实上**：长效型资料没有事实，最主要的参考资料将无法按领域筛选；改为挂在资料上，靠"提及不计入"控制事件领域的噪声。
- **以事实为跟踪单位**：同一事件一天多条事实会刷屏；以事件为单位后不再需要相似报道折叠。
- **名录外也存未收录实体**：用户要求实体一定是预设或人工通过的；改为待确认实体保留出现记录，同样免去回填检索。
- **提及挂在事件上**：事件合并时需另行迁移；挂在事实上随事实移动。

## 后果

- 图谱会比较稀疏：最常见的"某公司发布某产品"对象不是实体，不成边。
- 实体列表须能整体放进资料理解提示词；超过约数百个时，需先用原文精确匹配筛出候选列表（届时再定）。
- 归组质量依赖模型，待验证：归组评测（标注 100–200 对，同时决定复核是否换厂商）、召回阈值扫描（0.6 / 0.85，并确定无日期资料的高置信阈值）、修订乱序重放、资料理解一致率（重点检查综合稿是否被抽出事实）。
- 现有按库已读状态取消，用户只能靠事实时间判断新旧。
- `CONTEXT.md` 中"领域""事实""事件""实体"以新含义恢复使用；开放实体抽取与身份判断仍为已删除概念。
