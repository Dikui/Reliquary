# 0014 内部资料库：五个库、知识图谱与 Markdown 收录

Status: accepted
日期：2026-10-14
部分取代 [0001](0001-postgres-only.md)（不使用 Neo4j 与 Redis）、[0009](0009-kb-collect-store-retrieve.md)（唯一知识库、收录时不抽关系、内容类型决定保存方式、处理待复核）、[0010](0010-postgres-task-queue.md)（PostgreSQL 任务队列）、[0012](0012-ingest-only-no-collection.md)（完整材料含原始文件、服务端解析文件、按原文链接补全）、[0013](0013-user-documents-imported.md)（`mine/`、`reports/` 目录规则）

## 背景

2026-10-13 目标改变：Reliquary 从外部资讯收录组件，变为个人 AI 工作平台的内部资料库。外部资讯只是来源之一，此外还有本人的工作资料、经验与 AI 生成的报告。不同来源的可信度和处理规则不同，检索时不能互相干扰。用户还要求知识图谱，以便按实体关系找到普通检索找不到的资料。

讨论中评估了两条路线：以上游 WeKnora 最新版为底座删减，或在 Reliquary 上扩展。两次只读评估见 `docs/tasks/weknora-eval-01/report.md` 与 `docs/tasks/weknora-eval-02/report.md`。按最终范围，在 Reliquary 上扩展约 111 至 186 工程日，以上游为底座约 139 至 232 工程日；难点（库模板、全局实体、图谱正本、长文分段、测评、调用统计）两条路线都要新做。本 ADR 采用在 Reliquary 上扩展的路线，缺少的能力按边界从上游移植。

## 决策

### 定位与边界

- 仍是单用户、单空间（[0007](0007-personal-single-user.md)），仍不负责采集（[0012](0012-ingest-only-no-collection.md) 的职责边界保留）。
- 资料只通过收录接口（HTTP 与 MCP）进入。站内不提供问答、自动 Wiki、Agent、数据源同步。外部 Agent 通过检索接口、图谱检索接口与 MCP 使用资料。
- 所有 API Key 可访问全部库，不按 Key 或 MCP 接入点限制库和工具。

### 五个库与模板

- 系统固定五个库，用稳定 ID 和英文目录标识，显示名称可改。按 [0011](0011-domain-names-in-code.md) 的原则，代码、表结构、HTTP 与 MCP 字段统一改称 `Library`（如 `libraries` 表、`library_id`、`library` 参数），取代 `KnowledgeBase`、`knowledge_base_id`；界面称"库"。改名作为最早的实现任务之一完成，避免后续任务在旧名字上改动。

  | 库 | 目录 | 模板 | 放什么 | 关注动态默认 |
  | --- | --- | --- | --- | --- |
  | 官方信息 | `official/` | 外部时效型 | 官方、公司、媒体、研究机构发布的新闻、公告、财报、研报、政策 | 开 |
  | 媒体信息 | `media/` | 外部时效型 | 外部个人的观点：专家、分析师、KOL 的评论与文章 | 开 |
  | 参考文档 | `references/` | 外部长效型 | 长期引用的资料：论文、书籍、标准、官方文档、教程 | 关 |
  | 个人产出 | `personal/` | 自有型 | 本人的工作资料、经验、SOP、笔记 | 关 |
  | AI产出 | `ai-output/` | 生成型 | 外部 AI 按要求写回的报告 | 关 |

  有时效的机构研报放官方信息；被当作定义和方法长期引用的白皮书放参考文档。

- 模板按处理机制划分，不按内容划分。去重、转载归并、来源证据、是否处理跟随模板，不能单独修改：

  | 模板 | 来源证据 | 识别同一份资料 | 其他 |
  | --- | --- | --- | --- |
  | 外部时效型 | 必须有链接；可按库配置为"链接，或机构名称加发布日期，二选一"，后者标记来源未核实 | 链接与正文；无链接时按正文及"机构、标题、发布日期" | 转载归并、相似报道折叠 |
  | 外部长效型 | 链接或标识 `identifier`（如 `doi:...`、`isbn:...`）之一 | 链接、标识与正文 | 不讲时效 |
  | 自有型 | 不需要 | 可选的来源标识 `source_ref` 与正文 | 见"同一份资料的新记录" |
  | 生成型 | 不需要 | 不去重 | 不审核、不处理，只建索引；标记为"不能当作事实" |

- 每个库可配置：名称、说明、收录审核标准、来源证据规则（仅外部时效型）、内容类型清单、每个内容类型是否抽取图谱、关系类型清单、是否进入关注动态。用户可从模板新建库。
- 资料入库后不能换库，放错只能删除后重新收录。
- 所有库共用一个向量模型，作为空间级配置。

### 收录

- 只接收 Markdown 正文加图片。图片先上传为附件，正文引用。不再接收 PDF、Office、HTML、音频、表格、JSON 等文件，不保存原件；调用方负责把这些形态转成 Markdown，表格转成 Markdown 表格。删除服务端文件解析（anydoc、MinerU、DuckDB）。
- 调用方必须指定库。`list_libraries` 返回各库的用途、该收与不该收的内容、审核标准与去重规则，接口文档同样写明。
- 外部长效型库接受可选字段 `identifier`；自有型库接受可选字段 `source_ref`；其他库不接受这两个字段。
- 可选的 `graph: true/false` 覆盖图谱抽取开关。
- 正文只设约 500 万字的安全上限。超过模型一次读取范围的长文，收录审核、摘要、实体、主题、关系都分段处理再合并。审核中的纯辅助分段（参考文献、脚注、页脚、导航、孤立标题等）为中性；全部分段审核完成、至少一段有符合标准的实质正文且没有明确不合格的分段时，整篇通过。仅有辅助内容或任何正文分段明确不符合标准时，整篇进入收录待审；调用或输出格式失败保留失败重试。分段条件不变。
- 补全沿用 [0012](0012-ingest-only-no-collection.md) 的规则，但按条目 ID 定位，不再按原文链接定位；缺失项只剩图片。补全把图片引用替换为本地路径后，重新计算正文位置。

### 同一份资料的新记录（自有型）

- 同一 `source_ref` 再次提交：正文与已有记录相同时视为重复，不新建；正文有变化时另存一条带时间的新记录，旧记录保留，不设版本号。
- 检索照常返回旧记录，并标明"有更新的记录"；冲突由使用方按时间判断。
- 图谱只采用同一 `source_ref` 下最新一条记录的关系；新记录处理完成后，旧记录产生的关系来源随之撤除。

### AI产出

- 外部 Agent 统一通过 HTTP `/api/v1/ingest` 或 MCP `ingest` 写回，指定目标库、标题、Markdown 正文与 `acquisition: "model_written"`。来源引用写在正文中。原报告专用入口已移除，已有报告的关联资料、实体与主题保留读取。
- Reliquary 不审核、不调用模型处理：不生成摘要、内容类型，不抽实体、主题、关系；只按调用方给出的字段写表头并建索引。关联实体只能引用已存在的实体，不新建。
- 同一请求的重试按内容指纹幂等，不会生成两份；这是接口幂等，不是去重。

### 审核与去重

- 除 AI产出外所有库都审核，标准按库配置。取消"处理待复核"；待处理页面保留收录待审与待补全两个标签。
- 去重、丢弃记录、转载归并、相似报道折叠都只在库内进行。同一链接在不同库互不影响。

### 处理调用（AI产出除外）

- 一次模型调用（长文每段一次）产出：摘要、内容类型、实体、主题、实体间关系，以及每张图片的说明文字（图中文字、数字、图表含义，结合上下文）。
- 内容类型只作筛选标签，不再决定保存方式。所有资料一律全文保存，取消"摘要加链接"。模型拿不准时选"其他"。
- 是否输出关系由"库加内容类型"决定，在同一次调用中判断，不额外调用模型；"其他"默认不抽。用户修改内容类型时补抽或撤除关系。各库各类型的默认值见库配置初稿。
- 关系类型以库的清单为准；清单里没有相近类型时自动补充并写操作日志，相近类型归到已有类型；用户可在库设置中合并关系类型。
- 图片说明作为该资料的附加检索块保存，指向图片所在段落，不写回正文。

### 知识图谱

- 实体沿用全空间统一的实体档案（[0002](0002-global-entity-registry.md)），六种实体类型不变。关系两端是全局实体 ID。
- PostgreSQL 保存关系正本：主体、关系类型、客体、来源资料（按资料计数）、来源库、媒体信息的发言人、正文位置；用户删除的关系留抑制记录，重新处理时不再抽出。
- Neo4j 是只读查询副本，节点为全局实体 ID。必须遵守：
  1. 所有修改只改 PostgreSQL，Neo4j 只由同步任务写入；
  2. 修改与同步记录在同一事务提交；
  3. 同步按"重新读取当前状态"写入，可重复执行，按实体串行并校验版本，防止旧任务覆盖新状态；
  4. 启动时与定期补推未完成的同步记录；
  5. 每天核对并以 PostgreSQL 为准修正；
  6. 提供全量重建，恢复备份后自动执行。
- 补全后重抽、改内容类型、合并实体、删除资料、删除单条关系、同一 `source_ref` 出现新记录，都要同步更新关系与来源计数。
- 图谱检索接口：输入实体名或 ID，必须指定库，支持 1 到 3 跳关系与两实体间路径；检索时不调用模型；结果带来源资料、来源库、发言人、位置，并返回尚未同步的记录数。
- 网页在实体页按关系类型分组列出关系，不做可视化关系图。

### 检索

- 普通检索为 BM25 加向量混合检索，加重排。必须指定库，可同时指定多个；过滤在候选阶段执行。保留按内容类型、实体、主题、时间、星标筛选和库内相似折叠。
- 向量与重排改为调用阿里云百炼 API（2026-10-16 修订，原定本机 Ollama 运行纯文本 Qwen3-Embedding-0.6B）：向量用多模态 `qwen3-vl-embedding`，1024 维（已有该维度索引），文本与图片同一向量空间并开启图片向量；重排用纯文本的 `qwen3-rerank` 一类模型，图片以图片说明文字参与重排。正文、图片与查询会发送到阿里云。模型不可用时，入库的向量任务排队重试，检索退回全文检索并标明。
- 更换向量模型时，后台用新模型另算一套向量，期间继续使用旧向量；用测评集对比后再切换并删除旧向量。

### 位置引用

- 原件不存在，位置只定位到 Markdown 正文：标题路径、段落序号、字符范围，以保存后的正文为坐标。每个检索块保存位置，检索与 MCP 返回位置，网页点击引用跳到正文对应段落并高亮。不约定页码或时间标记。

### 关注动态

- 按库开关，默认值见上表。各库分别记录上次查看时间：打开"全部"更新所有库，打开某个库只更新该库；"全部标为已看"按当前范围生效。相似折叠只在库内。MCP `follow_feed` 可选库参数，不传时返回所有开启动态的库，读取不更新上次查看时间。
- 主题由用户定义，可选适用库（默认全部）；主题历史归入不产生新动态。

### 测评与调用统计

- 记录每次检索；提供测评集管理（手工添加、从检索记录转题、AI 生成候选后人工确认、标准答案资料被删时标出）；运行评测并保存检索配置快照，指标为精确率、召回率、MRR、NDCG、MAP（按评估报告修正分母）；两次结果可按题对比。
- 每次模型调用记录时间、模型、用途、所属资料、输入输出 token、单价快照与费用、耗时、成败，网页按模型、用途、时间汇总并画趋势图。不部署 Langfuse。

### 存储与任务

- 只保留实际部署的后端：PostgreSQL（ParadeDB）、本机磁盘、Redis、Neo4j。不使用独立向量库和对象存储，代码中不保留其他后端。
- 任务队列改用 Redis（asynq），取代 [0010](0010-postgres-task-queue.md) 的 PostgreSQL 队列。业务事务写入 PostgreSQL 待处理操作，提交后推入 Redis；Redis 只承载唤醒，任务状态、延后、终态与死信以 PostgreSQL 为准；Redis 丢失时从待处理操作重推。任务执行仍是至少一次。

### 文件库

- 每个库一个英文目录；`attachments/<资料id>/` 只放图片。
- 所有库共用一套表头：公共字段加各库可选字段，新增 `source_ref`、`identifier`。表头仍由数据库单向写入。
- `.reliquary/` 维护副本在原有内容之外，增加不能重新生成或重新生成代价高的数据：关系正本与来源、关系抑制记录、关系类型及其合并、测评集与标准答案。检索记录与模型调用统计只随 PostgreSQL 备份，不进副本。

### 维护

- 备份包含 PostgreSQL 与文件库。恢复后重推 Redis 任务、重建 Neo4j；新增的持久表都要有维护归属。

## 后果

- 调用方承担格式转换与 AI产出格式的质量：扫描件识别、表格转换、录音转写的好坏取决于 Grok Bot 等外部工具，Reliquary 只能用获取方式字段标明。
- 没有原件，网页无法打开原 PDF 或回放录音核对。
- 部署从"PostgreSQL 加文件"变为四个服务：PostgreSQL、Redis、Neo4j、Reliquary，外加服务器本机的 Ollama 与重排服务。评估实测四服务空载约 0.55 至 0.7 GiB，建议预留 2 至 3 GiB。
- 图谱在 PostgreSQL 与 Neo4j 各存一份，副本可能短暂落后，需要同步、核对与重建机制。
- 长文分段让模型调用次数随长度增加；调用统计用于观察费用。
- AI产出不进入实体档案和图谱，只能通过检索和关联资料找到。
- 0009 中"需要关系时由外部 AI 现场分析"的取舍不再成立，关系在收录时抽取，可能抽错，由用户删除与抑制修正。
- 现在没有生产数据，不需要迁移；按新基线重新开始。ADR 接受后同步更新 `CONTEXT.md`。
