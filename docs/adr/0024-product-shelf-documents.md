# 0024 产品货架的资料文件、版本与解析

Status: proposed
日期：2026-11-07
修订：[0014 内部资料库](0014-internal-knowledge-base.md) 中只收 Markdown、不解析文件、不保存原件、同库同来源新提交覆盖正文且不保留旧版的规则，以及 [0022 产品库的关联与演进](0022-managed-catalog-evolution.md) 中按正文名称自动关联产品的规则；均仅限开启货架的库，其他库不变。

## 决策

资料文件是货架概念，含若干版本。每个版本保存原件（本机附件目录，计入完整备份）或云盘链接、解析得到的文本版（作为库中的一条资料）、版本号（优先客户写法）、初稿或终稿标记与来源。资料文件挂在型号、产品名称、平台或部件上，由下属型号或使用该部件的型号共用，按型号、部件、产品名称、平台的顺序取第一个；可指向一项资料要求；证书与报告挂在认证记录上。

资料要求是客户资料清单的一行，绑定产品线或模块类型，各自记录初稿应交阶段（可空）与终稿应交阶段；阶段名与顺序是库配置，代码不写死。型号的资料清单是计算视图：应有项为其产品线与组成中各模块类型的资料要求，按当前阶段与当前版本给出已交、只有初稿、缺、未到期。清单按最新版资料要求检查。

资料文件与货架的关联只由提交方（网页或 agent，经变更集确认）明确指定。资料与产品放在同一个货架库，该库不对本库或其他产品库做正文名称自动匹配（人工维护库原本始终匹配本库产品）。每个版本单独建索引并标记是否当前；检索默认只查当前版本，可包含历史版本，同一文件多版本命中时合并。

PDF 解析在库设置中配置：命名解析器（外部 HTTP 服务、视觉大模型、不解析），默认解析器加按扩展名、资料要求、文件类别的规则；解析走后台任务队列，最终失败保留原件并可换解析器重解析。输出统一为 Markdown 加页码标记。文件大小上限可配置。具体解析器另行选型。

## 取舍与验证

客户资料以 PDF、图纸、证书为主，需要下载原件，外部转换后只交 Markdown 不能满足；改为按库开启，以免影响个人使用。名称自动匹配会让汇总类文件关联大量型号，且与跨类别同名冲突，因此货架库改为只认显式关联，代价是未指定归属的文件不进入节点范围检索。保留历史版本索引以便追溯，默认过滤以免引用过时内容。不保存解析中间结果，不做服务端 Office 解析。

验证资料清单四种状态与上层、部件共用，版本替换后默认检索只命中当前版本，包含历史时合并结果，解析失败保留原件，原件随完整备份与恢复保留。迁移只新增结构，存在货架资料版本时拒绝降级。

## 修订（2026-11-08）

资料要求的身份改为“所属清单 + 名称”：不同清单（导入方案中的工作表或手工指定的清单）的同名资料要求各自独立，同一清单内名称唯一。一个资料文件可以满足多项资料要求，清单计算对每项要求分别判断。依据：客户 5 张 ATQ 清单 180 行只有 121 个不同名称，按名称识别会让清单之间互相覆盖负责人、应交阶段与市场。
