# 0005 事件层只记录对象时间线，关联最多展开一层

Status: superseded
被 [0009](0009-kb-collect-store-retrieve.md) 取代
日期：2026-10-08

## 背景

事件表示与对象相关的一次具体变化，多条消息只有描述同一次现实变化时才聚合为同一个事件。
不同变化可以属于同一条发展脉络，但若把事件关联当作可遍历的图，查询、权限投影和推理的复杂度会持续增加。
本项目使用 PostgreSQL 保存可追溯的结构化知识，综合分析由 Agent 完成，需要明确事件层的职责和复杂度上限。

## 决策

- 事件只作为对象的时间线记录，保存具体变化及其来源证据，不建立独立的图推理系统。
- `same_occurrence` 仍表示同一次现实变化并合并事件；`same_story` 仍表示同一脉络中的另一变化并保留独立事件；`unrelated` 仍表示无关变化。沿用现有判断逻辑和提示词。
- 每个 `same_story` 关联只指向前一个事件。查询最多展开这一层直接关联，不继续展开被关联事件的关联。
- 数据层不做传递推理，也不把关联的传递关系当作新的事实、事件关系或来源证据。
- 多跳分析由 Agent 分多次查询完成，每次查询继续应用知识库或领域范围及来源证据可见性；数据层不执行递归查询或图遍历。

## 后果

- 按对象和时间查询事件即可构建时间线；直接关联帮助理解相邻变化，但不自动推导完整故事链。
- 关联查询成本和来源范围可以在一层内检查，不依赖事件链长度。
- Agent 需要显式选择下一次查询及核验其证据，多跳结果属于分析产物，不能当作数据层已经证明的结论。
- 若以后需要完整链路遍历或传递推理，必须重新评估本决策及其权限、性能和证据语义。
