# 0002 对象身份在团队空间内全局统一

Status: superseded by [0016](0016-library-catalogs.md)
日期：2026-10-07

## 背景

现有对象表的唯一约束是 `(tenant_id, knowledge_base_id, normalized_name)`，同一个"OpenAI"在两个知识库里是两个对象。
本项目要支持多个领域、多个知识库，同一个公司或人物经常跨领域出现，结构化对比和事件跟踪需要跨知识库汇总。

## 决策

对象和别名在团队空间内唯一，唯一约束改为 `(tenant_id, entity_type, normalized_name)`。
事实、事件、证据继续记录 `knowledge_base_id`，按知识库或领域过滤时通过证据实现。
迁移时按"规范名 + 类型"合并已有的同名对象，生成可撤销的合并记录；名称相同但类型不同的进入待合并建议，不自动合并。

## 后果

- 跨知识库查询同一个对象只得到一条记录，事实和事件自然汇总。
- 对象解析的候选范围变成整个团队空间，必须配合 top-K 召回（见 spec 6.4），不能再全量比较。
- 错误合并会影响所有知识库，因此合并操作要可追溯、可撤销。
- 前提是团队成员都能看到全部知识库（见 [0003](0003-single-team-space.md)）。2026-10-07 讨论过"指定成员可见"的知识库，因为会让全局对象的名称、描述和事实需要按证据过滤，已决定不提供。如果以后要引入，需要重新评估本决策。
