# 0009 知识库收窄为收集、存储、检索组件

Status: accepted
日期：2026-10-11
取代 [0004](0004-domain-templates-open-fields.md)、[0005](0005-event-layer-bounds.md)、[0006](0006-on-demand-structured-extraction.md)、[0008](0008-focus-precheck-and-backfill.md)；部分取代 [0007](0007-personal-single-user.md)

## 背景

2026-10-10 讨论把目标扩展为个人 AI 工作平台。Reliquary 作为其中的信息组件先行，只负责收集、存储、去重和检索，简报与报告由外部 AI 通过接口完成（`.scratch/ai-work-platform/discussion-2026-10-10.md`）。

原设计在收录时生成大量结构化数据：领域模板与开放字段事实、事件聚合与脉络、关注范围与补抽。[0006](0006-on-demand-structured-extraction.md) 的统计显示开放字段占事实的 97% 到 99%，且没有事实查询的使用记录。报告改由外部 AI 撰写后，收录时预先生成的关系和事实缺少使用方，而维护成本（模板、归并、补抽、事件拆合）持续存在。

原文和用户判断是需要长期保存的资产，希望在项目之外也能直接阅读。

讨论过程见 `.scratch/ai-work-platform/discussion-2026-10-11-kb.md`。

## 决策

### 存储

- 文章正文以 md 文件保存在服务器的文件库中，可用 Obsidian 阅读。正文写入后不再改动。
- 数据库（PostgreSQL，[0001](0001-postgres-only.md)）保存索引、去重记录、实体档案、主题、用户判断、处理状态和操作日志。
- 表头字段以数据库为准，由程序生成并单向写入文件。渲染结果确定（字段顺序、列表排序、格式固定，不调用模型），内容不变时不写文件。不反向同步 Obsidian 中的修改。
- 只有审核通过的文章写入文件库。用户文档放 `mine/`，程序只读并建索引；整理结果放 `reports/`。
- 文件库只在内网，暂不做多设备同步。

### 收录

- 只保留一个知识库，删除领域。
- 去重与转载归并保留。各收录入口统一模型审核，调用方判断不替代审核。待审区分为收录待审与处理待复核。
- 一篇文章收录时由大模型产出：内容类型、按统一模板的摘要、实体、主题。内容类型决定处理方式：事件、观点、研究全文保存；教程、案例、参考只存摘要加链接。类型拿不准时记录模型类型和原因，一律全文保存并进入处理待复核，不阻塞入库及检索。
- 上传和录入缺原始链接时先从文件元数据及明确来源标注中提取，不联网搜索；仍缺链接时直接收录待审。用户可补链接重新审核、确认无链接入库并标记来源未核实且全文保存，或转为本人文档。
- 实体识别后归一到实体档案（[0002](0002-global-entity-registry.md) 的全局身份保留）。
- 收录时不抽取关系、事实、事件。这些由外部 AI 在检索、整理、总结时读正文现场分析，引用指向正文。
- 主题由用户定义，一篇文章可属于多个主题。新建主题时用历史摘要批量归入。
- 订阅源（RSS）改为全局配置，可设默认内容类型。

### 检索

- 混合检索：全文索引覆盖表头和正文；向量包括带“标题 · 来源 · 日期”前缀的正文分块、标题加摘要的文章级向量和用户文档。命中结果按文章合并。
- 相似报道在检索时按摘要向量相似度加时间窗口折叠，不保存分组。
- 按内容类型、实体、主题、发布时间、星标筛选。

### 入口

- 恢复对外接口：收录接口（供内网的 Grok Bot 等调用）和 MCP 服务（检索、读取文章、收录、待审区、星标等）。取代 [0007](0007-personal-single-user.md) 中“只保留 Web 界面一个入口”和删除 MCP 服务端的部分。
- Obsidian 只用于阅读；审核、星标、修正、实体合并、主题和订阅源管理在精简后的网页界面完成。
- 网页不再提供问答。问答、整理、写报告由外部 Agent 通过收录接口和 MCP 完成。

### 删除

领域、领域模板、开放字段、字段归并、事实记录及纠正、结构化检索、证据快照版本、抽取模式、关注范围、名称预判、补抽、事件聚合、事件脉络与热度、具体所指标签、内容性质标签、自由标签、关注价值评分、Agent 策略、原文更新审核、分块编辑与修订历史、消息纠错与来源冲突、跟踪工作流、研究报告、多知识库、站内对话、自定义智能体、DuckDB 数据分析、MCP 客户端。

## 后果

- 收录时每篇文章的模型调用基本固定为一次（审核另计），不再随关注范围变化；不存在“加星标后历史没有覆盖”的问题，新建主题只需对摘要做批量判断。
- 需要关系、事实对比时，每次分析都要重新读正文，单次分析成本和耗时上升。分析结果可存为整理结果以免重复。
- 没有事件时间线。需要时由外部 AI 按实体和时间检索后现场整理。
- 摘要加链接的文章只能检索到表头内容，原网页失效后正文不可恢复。
- 文件库与数据库并存：数据库丢失时可从文件库重建正文和表头中的用户判断；摘要、实体、索引需要重新生成。
- 只在内网访问，外部云端 Agent 无法使用。以后开放外网时需要重新评估认证与暴露范围。
- 现有数据全部清空，不迁移；改造完成后重新收录。
