# 0008 关注范围先判断、时间线提示与可选补抽

Status: superseded
被 [0009](0009-kb-collect-store-retrieve.md) 取代
日期：2026-10-09
部分取代 [0006](0006-on-demand-structured-extraction.md) 的收录流程

## 背景

[0006](0006-on-demand-structured-extraction.md) 的收录流程是：第一轮用精简提示词识别对象并抽模板字段事实，对象解析后判断是否命中关注范围，命中则每段再跑一次补缺轮（开放字段事实与事件）。命中的消息因此读两遍正文、发两次请求。

0006 同时规定加星标不重抽历史消息。给对象加星标后，它的事件时间线从这之后才开始，之前收录的相关消息只有模板字段事实，时间线、热度和基于事件的报告容易被误读为完整历史。

## 决策

### 先判断，再抽取

在调用抽取模型之前，用已有数据预判消息是否命中关注范围：

- 主题：消息的具体所指标签（收录审核时已生成）与星标主题、跟踪任务涉及的主题比对。
- 对象：星标对象与已启用工作流事实查询条件中的对象，取规范名和全部别名，与正文做精确匹配。
  - 名称与正文用同一规则归一化：大小写、全角半角、连续空白，连字符与空格视为等同。
  - 含中日韩字符的名称按子串匹配；由字母和数字组成的名称要求词边界。
  - 字母和数字组成且不超过 3 个字符的名称要求大小写完全一致。

预判命中：每段用完整提示词抽取一轮，一次得到对象、模板事实、开放字段事实和事件。对象解析后，若解析结果不涉及关注范围（预判误判），丢弃本次产生的开放字段事实与事件，只保留对象和模板事实，证据记为 `template_only`。

预判未命中：沿用 0006 的流程。第一轮精简抽取，对象解析后若命中关注范围（例如正文只有"该公司"等间接说法，由模型识别），再跑补缺轮。补缺轮由必经步骤变为兜底。

对象解析已把新出现的叫法保存为别名，下次同样的叫法可在预判中直接命中。

关注范围的定义、`extraction_mode` 的含义与记录方式、范围外消息只保留模板事实的规则保持 0006 不变。

### 时间线提示

事件时间线、对象档案和知识报告中，凡展示事件或基于事件统计的地方，注明"只包含收录时命中关注范围的消息"，并显示与当前对象或主题相关、最新证据版本仍为 `template_only` 的消息数。计数按证据与对象的关联、消息与具体所指标签的关联统计。

### 可选补抽

- 触发：只能手动。星标对象或主题的档案及关注范围视图提供"补抽历史消息"操作，显示待补抽消息数和预计模型调用次数，用户确认后执行。加星标后在同一位置提示该操作，不自动执行。
- 范围：与该对象或主题相关、最新证据版本为 `template_only` 且抽取已完成的消息。每批最多 200 条，从发布时间最新的开始，界面显示剩余数量。
- 内容：在原有不可变证据快照上只跑补缺轮，不重新抓取或解析来源，不重跑第一轮。补缺轮所需的对象由该证据已关联的对象还原，使用其规范名和全部别名。已有的对象、别名、模板事实及其纠正保持不变。
- 模板：使用补抽时领域模板的当前内容，证据记录补抽时间及所用模板的更新时间。之后模板再变更不触发重抽。
- 结果：成功后证据的 `extraction_mode` 改为 `full`。事件走现有的聚合判断（`same_occurrence` / `same_story` / `unrelated`），独立来源数沿用现有规则。不重写已有事件之间的关联。
- 执行：每条消息一个任务，放在维护工作池，沿用现有重试与死信。单条消息在一个事务内写入，失败时保持 `template_only`，不留下部分结果。消息正在重新处理时跳过并计入失败原因。
- 记录：每个批次记录发起的对象或主题、消息数、成功数、失败数。
- 取消星标不删除补抽结果。

## 后果

- 正文点名星标对象的消息只读一遍正文、发一次请求；调用预算从 2S + U + E + A + B 降为 S + U + E + A + B（符号同 0006）。只有间接说法的消息仍为两轮，召回与 0006 相同。
- 预判误判（名称相同但不是同一对象）多花一次完整抽取的输出，结果被丢弃，不污染数据。短名称限制用于降低误判，不能消除。
- 完全没有可识别名称的消息，两种流程都会漏判。
- 补抽让时间线可以按需补齐，代价是每条消息约 S + E 次调用。补缺轮看到的是对象的规范名和别名而不是第一轮的原始提及，可能少抽。
- 补抽事件按发布时间插入时间线，已有事件的 `same_story` 关联不重排，脉络可能出现不连贯处；多跳分析仍由 Agent 完成（0005）。
- 同一对象新旧消息可能依据不同版本的模板抽取，证据记录的模板更新时间用于解释差异。
