# 0023 产品货架的结构与写入方式

Status: proposed
日期：2026-11-07
修订：[0021 库级人工维护实体](0021-managed-entity-library.md) 与 [0022 产品库的关联与演进](0022-managed-catalog-evolution.md) 中名称唯一不区分类别的规则，仅限开启货架的人工维护库。

## 决策

产品货架是人工维护库上按库开启的通用能力，合入主线；客户专属内容（产品线、模块类型、区域、资料要求、阶段值）只以数据或库配置存在。保持单用户与无登录。存储沿用人工维护实体、关系、属性快照与操作日志，货架特有逻辑放在其上的服务层。

结构固定为：产品线、产品平台、产品名称、产品型号四级层级；部件按模块类型划分，型号通过带模块类型的组成关系指向部件，同一模块指向多个部件即为选配；型号与部件始终是不同条目，单卖的部件型产品是只含一个部件的型号。型号下挂可售状态、认证、资料文件与参数。任一条信息可附加适用条件，形式为若干“模块类型 ∈ {部件}”的合取，空为全部适用；按组合查询返回条件被满足的信息，未给组合时返回条件本身。部件认证在型号上标为来自部件，部件与型号的状态不联动。不可选组合使用同一条件写法，预留不实现。

名称由客户定义，原样保存，身份以 ID 为准。货架库内名称、别名、代码按类别唯一；不同类别同名须经确认才保存，确认结果持久化，界面与 agent 输出用类别区分。

所有写入（Excel 导入、网页编辑、外部 agent）先生成变更集：校验、差异与冲突、确认后单事务写入，失败整体回滚。货架为主数据，表格只是变更提议，不覆盖手工值，消失的条目不自动删除。agent 只用一个通用的提交变更集工具，未确认时只返回差异并保存待确认变更集。操作日志记录来源（网页、agent、导入批次）。

## 取舍与验证

不为货架单独建表，以复用修订、历史、导出恢复与图谱副本；几百个型号的规模下按 JSON 属性查询足够。不把选配展开为完整配置实体，避免组合数膨胀。不保留各类别共享的名称空间，因为客户数据中平台、产品名称与型号同名（如 EG-ODM）。不做一键撤销与按 agent 的权限。

验证组成与选配、适用条件匹配、来自部件的认证、跨类别同名确认与同类别拒绝、变更集冲突分类与回滚、手工值不被覆盖、操作日志来源。名称唯一规则的迁移只放宽货架库约束，不改变普通库行为。
