# 0023 产品货架的结构与写入方式

Status: proposed
日期：2026-11-07
修订：[0021 库级人工维护实体](0021-managed-entity-library.md) 与 [0022 产品库的关联与演进](0022-managed-catalog-evolution.md) 中名称唯一不区分类别的规则，适用于所有人工维护库。

## 决策

产品货架是人工维护库上按库开启的通用能力，合入主线；客户专属内容（产品线、部件类型、区域、资料要求、阶段值）只以数据或库配置存在。保持单用户与无登录。存储沿用人工维护实体、关系、属性快照与操作日志，货架特有逻辑放在其上的服务层。

结构固定为：产品线、产品平台、产品名称、产品型号四级层级；部件按部件类型划分，型号通过带部件类型的组成关系指向部件，同一部件类型指向多个部件即为选配；型号与部件始终是不同条目，单卖的部件型产品是只含一个部件的型号。型号下挂可售状态、认证、资料文件与参数。任一条信息可附加适用条件，形式为若干“部件类型 ∈ {部件}”的合取，空为全部适用；按组合查询返回条件被满足的信息，未给组合时返回条件本身。认证可属于型号、部件、产品名称或平台；部件认证在型号上标为来自部件，产品名称或平台上的认证由下属型号共用并标为来自上层；部件与型号的状态不联动。不可选组合使用同一条件写法，预留不实现。

名称由客户定义，原样保存，身份以 ID 为准。人工维护库内名称、别名、代码按类别唯一；不同类别同名须经确认才保存，确认结果持久化，界面与 agent 输出用类别区分。

所有写入（Excel 导入、网页编辑、外部 agent）先生成变更集：校验、差异与冲突、确认后单事务写入，失败整体回滚。货架为主数据，表格只是变更提议，不覆盖手工值，消失的条目不自动删除；数据含义不确定时（如区域单元格为空、无法对应节点的认证行）作为冲突退回提交方选择，系统不推断。界面与外部 agent 共用一个货架查询服务，agent 留在 Reliquary 外部。agent 只用一个通用的提交变更集工具，未确认时只返回差异并保存待确认变更集。操作日志记录来源（网页、agent、导入批次）。

## 取舍与验证

货架条目不单独建表，以复用修订、历史、导出恢复与图谱副本；变更集、导入方案、同名确认等过程数据另建表；几百个型号的规模下按 JSON 属性查询足够。不把选配展开为完整配置实体，避免组合数膨胀。不保留各类别共享的名称空间，因为客户数据中平台、产品名称与型号同名（如 EG-ODM）。不做一键撤销与按 agent 的权限。

验证组成与选配、适用条件匹配、来自部件的认证、跨类别同名确认与同类别拒绝、变更集冲突分类与回滚、手工值不被覆盖、操作日志来源。名称唯一规则的迁移只放宽人工维护库约束，不改变自动抽取库行为。

## 修订（2026-11-08）

真实数据验收后，用户确认：导入只保证功能正确，不为客户数据异常做专门处理。对不上的所属节点、一格多个标准、缺少的列、条件格式等一律作为冲突列出，由提交方用通用的修改、放弃、暂缓、加别名逐条处理。可售状态的来源按区域记录，编辑一个区域不改其他区域的来源。导入批次列出未映射但有内容的列。型号页提供编辑入口，编辑同样生成变更集。

资料要求的名称、别名和代码改为同一所属清单内唯一，其他类别沿用按类别唯一。导入的所属清单由方案键与工作表名确定，手工新建由提交方指定。不同清单的同名要求各自保存负责人、应交阶段、市场和来源版本；同一文件可明确关联多项要求，分别计算状态。见 [ADR 0024](0024-product-shelf-documents.md) 的同日修订。

## 修订（2026-11-10）

资料要求只通过 `applies_to` 绑定产品线，移除部件类型绑定与部件自身的应交资料清单。部件类型继续用于组成、选配及适用条件；部件仍可挂资料文件，由使用该部件的型号按原优先级共用。不转换旧的部件类型绑定，读取时忽略其清单适用性，保留原数据供人工处理。

资料要求的市场与型号可售区域分别配置。市场列表由货架设置保存为库配置，客户专属市场名不写入代码。没有要求、历史或导入方案引用的市场可删除，已有引用的键保留身份。ATQ 方案支持多列映射到同一市场；转换后的必需性不一致时返回含义不确定冲突，不选择其中一列。方案级 `market_values` 保存原文到必需性枚举的明确映射。

通过 API Key 上传表格时，导入变更集的 `source.agent_name` 记录该 Key 的名称；本机无凭据网页上传不填。重复上传仍复用同一批次与原来源，不改写原提交方记录。
