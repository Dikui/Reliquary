# 新产品上架

你替用户把一个新产品（同一产品名称下的一个或多个新型号）上架到产品货架。资料清单不逐条建：型号挂到产品线和平台后，按绑定的资料要求和在售市场自动得出。先读 [使用规则](../rules.md) 和 [货架专家](shelf-expert.md)，再调 `shelf_guide`（不传节点）读本库可用值和补充规范。用户给的是 Excel 时改按 shelf-import 流程。

## 范围

- 只在已有产品线下上架，不新建产品线；产品线不存在时停下，请用户先在网页的货架设置或产品地图中建好。
- 平台、产品名称可以已有，也可以在同一变更集中新建。
- 一个变更集只放一个产品名称下的型号；多个产品名称分批提交，上一批确认后再做下一批。
- 只新建，不改已有型号。型号名已存在时停下，说明这是修改已有型号，改按 shelf-expert 维护。

## 一次问齐的信息

开场把下列问题合成一张清单一次发给用户，已在对话里给出的不再问。选项取自 `list_libraries` 和 `shelf_guide` 返回的本库配置，列出供选择，不自造。

必填：
1. 产品线（列出本库产品线）。
2. 平台、产品名称：已有的给名称，新建的给原样名称。
3. 每个型号的原样名称，可附代码和别名。
4. 每个型号各区域的可售状态（取本库 regions 和状态值）及生效日期；没有的区域留空，不补成待定。资料清单按这些状态对应的市场筛选，没有在售市场时清单为空。
5. 认证清单来源，三选一：参照某个已有型号复制；用户逐条给出（标准、认证对象、地区，可附机构、计划取证日期）；暂不建认证。

选填：
6. 组成部件，特别是电芯：已有部件给名称，新部件给原样名称和部件类型（取本库 module_types）。认证按电芯区分时必须给电芯。
7. 参数：只列本产品线可用的参数字段（entity_schema.fields 中 product_line_ids 含该产品线的字段）及单位。
8. 当前阶段（取本库 stages），通常设在产品名称上。用户不给就不设，不推测。
9. 描述、备注。

## 步骤

1. **核对身份，不写入。** 对每个平台、产品名称、型号和部件名称调 `shelf_find`，翻完分页。用户说“已有”的必须唯一命中同类别节点；说“新建”的不能命中同类别名称、别名或代码。命中其他类别的同名节点时，列出候选，请用户确认后在操作里写 name_confirmations。对不上的先问用户，不猜。
2. **读参照型号。** 认证选“参照复制”时，`shelf_get` 读参照型号，列出它自己的认证记录（owner 是该型号的）。挂在上层（产品名称、平台）或部件上的认证不复制：新型号挂在同一上层或用同一部件时自动共用，否则在报告里列出，请用户决定是否为新型号单独建。参照型号的认证有 conditions 时，问用户新型号对应哪个选配，或不带条件。
3. **定认证清单。** 参照复制的每条只取 standard、certification_object、region、agency；cell_part_id 换成新型号的电芯部件，参照型号有多个电芯而新型号只有一个时，同一识别键只保留一条；progress 写“待启动”。不复制 year、实际取证日期、证书编号、发证日期、有效期、链接、起止日期和备注；用户给了计划取证日期才写 planned_date。名称按“型号原名 / 标准规范名 / 认证对象原文”，有电芯加“ / 电芯部件原名”，有地区加“ / 地区名”。用户逐条给出的同样处理，缺标准、认证对象或地区的条目先问清。
4. **组一个变更集。** 按依赖顺序写操作，用 `$操作id` 引用本批新建的节点：
   - 新平台、新产品名称：create_entity（kind 为 platform、product；产品名称的当前阶段写在 attributes.current_stage），再用 save_relation 的 belongs_to 挂到上层（主体是子项）。
   - 新部件：create_entity，kind 为 part，attributes 写 module_type。
   - 型号：create_entity（kind 为 model），belongs_to 挂到产品名称；composed_of 连接部件，关系属性 module_type 必填。
   - set_sale_statuses、set_parameter_values，effective_at 用用户给的生效日期。
   - create_certification，owner_id 指向新型号。
   `shelf_submit` 只传 library_id、source（`{"type":"agent","agent_name":"<固定提交方名称>"}`）、operations，省略 confirmed，先保存待确认变更集。
5. **展示预览。** 先用一句话说明要建什么，再列：层级（新建的标出“新建”）、每个型号的组成、区域状态和参数、认证清单（参照来源、换掉的电芯、没复制的字段和上层共用的认证）、预计适用的资料要求清单（取 `shelf_guide` 中绑定该产品线或平台的 requirement_lists，说明确认后按在售市场筛选），以及每项冲突和你的建议。新平台没有绑定任何资料要求清单时要说明：新型号只会得到产品线上的清单，平台专属的要求须在网页另行绑定。
6. **处理冲突。** `new` 是正常的新建标记。其他冲突按 shelf-expert 第 8 步处理：含义不确定的修正、放弃或暂缓，身份类问题问用户。修正后重新读取变更集再展示。
7. **确认。** 用户明确说确认后，传同一 changeset_id、revision、逐项 decisions 和 `confirmed=true`。用户没有明确同意前不确认；用户只要求预览或演示时停在预览。
8. **报告。** 确认后对每个新型号 `shelf_get`，报告实际写入的层级、组成、区域状态和认证清单（附认证状态），列出应交资料清单与缺口，按 shelf-expert 说明检查市场、可选项和 checklist_skipped_reason；没有在售市场时说明清单为空的原因，不说成资料齐全。

## 输出格式

- 预览：本次要建的内容一句话、层级与新建标记、各型号组成、区域状态与生效日期、参数、认证清单及来源、预计适用的资料要求清单、冲突与建议、变更集 ID 和修订号。
- 确认后：实际写入结果、各型号认证状态、应交资料清单与缺口、检查市场或跳过原因。

## 停止条件

- 产品线不存在、型号已存在、身份对不上或认证缺识别字段时，先问用户，不先提交部分内容。
- 所需信息缺失且会改变写入内容时，一次列出缺的项再问；选填项用户没给就不写，不推测。
- 未取得用户对所展示差异的明确同意，不传 `confirmed=true`。

## 禁止事项

- 不新建产品线、市场、区域、阶段、部件类型或标准；本库没有的值请用户先在货架设置里加。
- 不复制参照型号的实际取证日期、证书信息和进度，不把参照型号的状态、参数或阶段套到新型号上。
- 不为补全资料清单逐条新建资料要求，不改资料要求的绑定范围。
- 不把一个新产品拆成多个变更集提交，也不在确认前写入任何一部分。
