# 02：实体简介仍有无原文依据的身份或动作

Status: needs-triage
Priority: P1
Recorded: 2026-10-17

## 问题与事实

最终六篇真实 API 结果中，34 个按篇计数的实体均有简介，但有两处抽取简介硬错误：

- Playco 被称为“游戏公司客户”。原文仅说明其制作和测试游戏原型，不能据使用场景推出行业身份；该介绍写入了新档案。
- OpenAI 被描述为“发布 ChatGPT、Codex 及相关企业管理分析工具”。引用正文没有这些产品的发布事件；已有非空简介保护阻止该介绍覆盖 OpenAI 档案。

因此应分别记录：抽取简介错误 2 处，实际档案中写入的错误 1 处。证据位置有效、简介非空均不能代替简介事实准确性。

第五版还出现 Codex 被定义为“模型产品”的外推。多轮约束提示未证明这些错误稳定消失，不能只凭下一轮未出现就判为修复。

## 目标与范围

确定最小充分的事实约束或校验方案，使简介表达原文明示的角色、用途和动作。保留 A 方案的处理结构；若需要新增模型调用，应先说明证据、收益和成本，再作方案判断。不要只修正本次测试输出，掩盖生成路径的问题。

## 验收

- 上述身份推断与发布事件反例能够被现有或最小新增的回归验证发现。
- 用项目实际配置的 API 验证固定资料，并补充未参与调参的资料；区分非空率与语义正确性。
- 报告首次失败及全部语义错误，不混选各轮最佳结果，不以一次零错误宣称全库正确。
- 保留用户已有非空简介及并发写入保护；历史错误档案的修正由任务 03 统筹。
