# 每周资料自检

Status: ready-for-human
Type: spec
Updated: 2026-10-23
Branch: codex/weekly-self-check

## Problem Statement

日常收录和处理后，资料仍可能重复、相互矛盾，或存在摘要、分类、实体、关系错误。用户需要每周集中发现这些问题，并查看原文证据；第一版不自动修复。

## Solution

程序每周选择新增或修改的资料，使用一个指定的已有模型执行已确认的[资料自检 skill](skills/reliquary-content-check/SKILL.md)，复用现有混合检索查找历史候选，将问题和证据保存到“辅助诊断 → 检查记录”。

| 类别 | 已确认规则 |
| --- | --- |
| 疑似重复 | 只查同库；文字相同或核心信息相同均检查，给出双方重合证据，不提醒新增内容 |
| 疑似冲突 | 允许跨库；按对象和核心信息判断，不因时间不同排除，给出双方矛盾证据，不裁定哪方正确 |
| 已有结果错误 | 只核对已有摘要、分类、实体、关系是否与原文不符或缺乏依据，不查遗漏，不重做抽取 |

无发现只能表述为“本轮未发现”。缺少必要数据或检查未完成时明确说明，不能当作没有问题。

## User Stories

1. As a 资料使用者, I want 每周检查新增或修改的资料并与历史资料对比, so that 我能发现三类问题而不必每周通读全部资料。
2. As a 资料使用者, I want 在辅助诊断中查看问题及原文证据, so that 我能自行判断并处理。
3. As a 维护者, I want 统一指定一个已有模型完成检查, so that 我无需配置多模型调度。
4. As a 维护者, I want 检查失败时收到提醒、保留已有结果并可手动复检, so that 故障修复后不会漏掉未完成资料。

## Implementation Decisions

### 程序接入

- 增加固定用途的自检执行流程，复用现有定时器、任务队列、模型调用和只读业务服务；不建设通用 Agent 平台。
- 程序负责每周触发、增量选择、模型选择、结果保存与展示、失败提醒和手动复检。skill 只负责检查方法、判定与输出。
- 增量以新增或修改的资料为起点，不按发布时间筛选。当前从空库开始，无需历史基线扫描；历史仅作为相关候选参与比较。
- 输入包括目标资料 ID、所属库、已有处理结果、可检索库范围、只读工具和原文定位信息。程序需提供核对所需的已有结果，不能假定现有正文读取接口包含全部结果。
- 检索复用现有关键词、向量与重排能力。关闭相似报道折叠，排除自身，不设时间筛选；按需读取原文、实体和关系证据，不要求每项固定运行所有工具。
- 三类检查使用同一个指定的已有模型；混合检索继续使用原有向量与重排配置，不增加检查模型之间的路由或自动切换。

### 运行与失败

- 保存每次运行的目标范围、模型、状态、已产出结果、失败原因和未完成范围，供查询与复检使用。
- 不设置自检用量上限。账号额度耗尽、服务限流或上下文超限时，停止整次检查并提醒，保留已有结果。
- 上述失败不得自动重试、换模型或拆分后继续。接入时须让自检遵循本规则，不沿用其他后台任务的额度延后或备用模型策略。
- 修复后由用户选择复检。复检须覆盖原未完成资料，不能因失败运行推进增量边界而漏掉它们；原有结果保留可查。
- 自检只写自身运行与结果记录，不修改资料正文、摘要、分类、实体或关系，不把问题加入收录待审。

### 展示

- 入口为“辅助诊断 → 检查记录”。能查看运行状态、结果，以及失败原因和未完成范围；失败记录提供手动复检入口。
- 结果按三类分组，每条仅含问题说明、涉及资料（标题、库、ID）、原文证据与跳转链接。重复和冲突列双方证据；已有结果错误列当前结果与原文。
- 链接使用真实的原文定位信息。缺少可用链接时保留资料 ID 和位置并说明，不编造链接，不输出评分或修复建议。

## Testing Decisions

- 验收范围已确认：能查出问题与证据，出错后停止并保留结果，修复后可手动复检。从“运行一次自检并查看结果”验收整个功能，不逐个测试内部函数。
- **正常检查**：用同库重复、跨库且时间不同的矛盾、已有结果错误等样例，核对三类问题及原文证据；不误报遗漏，不修改业务资料。
- **失败与复检**：模拟额度耗尽、限流或上下文超限，核对整次停止、提醒和已有结果保留；修复后手动复检，未完成资料不遗漏。
- **页面查看**：能找到检查记录、阅读问题、跳转原文；能区分无发现与未完成，失败时能查看原因并发起复检。
- 实现时优先复用现有批量任务的数据库、队列和可控模型测试；仅新增必要的正常运行与失败复检测试，不扩大测试体系。
- 需求整理阶段只核对文档；实现阶段用替身模型验证流程，语义准确性仍须用实际模型样例人工核对。

## Out of Scope

- 自动修复、合并、删除、重新处理、补齐遗漏、来源关联或生成新增信息提醒。
- 全量历史扫描、通用 Agent 平台、多检查模型调度、自动降级换模型、失败后自动重试或拆分续跑。
- 外部通知渠道、评分体系、新的检索系统，以及现有入库和后台处理规则的调整。
- 安装或启用 skill、配置真实模型与执行时间、部署或修改运行数据。

## Further Notes

- 规则以当前已确认的 skill 和[领域记录](../../CONTEXT.md)为准；先前被移出的草案不作为需求依据。
- 具体模型与每周执行时间尚未选定，在实际启用前确定；本文不擅自设置默认值或启用计划。
- 本需求包含固定用途的资料检查，不改变现有内部资料库定位，也不要求修改其他模型任务的失败策略。

## Implementation

- 已接入每周调度、增量范围、单模型只读检查、结果存储、失败提示和手动复检。
- 在“辅助诊断 → 检查记录”选择模型、执行日与北京时间后启用；默认关闭，未选择真实模型或执行时间。
- skill 由服务嵌入；本目录链接指向同一份规则，避免两份内容不一致。
- 只新增自检配置与运行表，不修改已有资料；未部署。
