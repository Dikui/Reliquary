# 三类资料入库与处理策略对照 V1

更新：2026-10-22。记录位置：`codex/library-redesign` 的 worktree。

本次交付是需求与源码事实对照，不改程序、数据库或部署。核对时 `main` 与本分支均为 `a32521b96d950df68f0393c89c82b5a610c24036`；不代表运行中的部署版本或库数量。

**结论：main 仍有模板、默认审核标准和处理机制。删除库只删除库实例及其配置，不会删除源码中的策略。** 当前已允许零库，启动、注册和旧文件库重建不会自动补建已删除的库。新建库仍会按所选模板填入默认策略。

标记：**✓ 已确认需求；△ 建议或待确认；main 为已核对的源码事实。** 本轮展示和讨论不视为用户批准新建议。

## 1. 三类资料要解决什么问题

✓ 资讯、参考资料、人工笔记分别保存于不同库。相同 URL 在不同库中分别存在，不跨库去重、覆盖或自动迁移。

| 项目 | 资讯 | 参考资料 | 人工笔记 |
| --- | --- | --- | --- |
| 使用需求 | ✓ 订阅、留存新鲜消息 | ✓ 保存产品报告、技术报告等，发现候选及进一步研究的线索 | ✓ 保存本人的笔记、思考和记录 |
| 内容审核的排除标准 | ✓ 仅为空泛评价或宣传口号，没有具体信息；空白、乱码、导航、占位文字等无信息内容 | ✓ 仅为空泛评价或口号，没有具体用途、功能、方法、经验、结论等参考信息；空白、乱码、导航、占位文字等无信息内容 | ✓ 只排除空内容和无法正常读取等异常；不设内容质量要求 |
| 内容不完整 | ✓ 接受摘要、片段和不完整资料 | ✓ 接受摘要、摘录、不完整报告；架构、全文、固定章节不是必需内容 | ✓ 不要求成稿、结论或固定内容字段 |
| 来源、篇幅和深度 | ✓ 不在已确认的两条排除标准之外追加来源、篇幅或完整度门槛 | ✓ 不追加链接、全文、架构或独立复现能力门槛 | ✓ 不要求外部来源、最低篇幅或公开发表质量 |
| 保存内容 | ✓ 可以只留标题、摘要和重点；△ 默认保存形态仍待确认 | ✓ 需能支持发现资料与继续调研；△ 默认精简说明还是全文仍待确认 | ✓ 完整保留提交原稿，摘要可选 |
| 使用时补充信息 | ✓ 不完整资料可供后续使用 | ✓ Web Agent 可进一步查询最新信息、架构和实现细节；这不是每篇资料的强制字段表 | ✓ 不自动改写本人的原稿 |

“审核标准”回答内容是否纳入；“处理标准”回答保存后补充什么信息。两者不混用。没有生成摘要或没有图谱，不等于原文没有价值。

## 2. 阻挡与审核分开看

“阻挡”在本表中是讨论用语。main 的收录接口没有统一的 `blocked` 状态，实际结果如下。

| 情况 | main 的行为 | 对三类需求的含义 |
| --- | --- | --- |
| 请求不合法 | 库未指定或不存在、正文为空、正文超过 500 万 Unicode 字符、非法字段或附件等返回请求错误；批量项为 `invalid` | △ 保留必要的技术校验；这些不是新的内容质量门槛 |
| 来源证据不足 | 资讯或参考不满足所属模板的来源规则时，保存内容并进入 `pending_review` | 与三类需求不追加来源门槛存在差别，需要后续改动，不能靠修改审核文字消除 |
| 模型判断不收录 | 按本库审核文字判断，未通过则保留正文，进入 `pending_review`；内部解析状态为 `rejected` | △ 建议继续保留待审，展示对应标准与原因，不自动删除 |
| 模型调用或输出失败 | 执行失败并按任务规则重试，不自动放行 | △ 建议保留现有失败与重试机制；它不代表内容被判无价值 |
| 内容重复 | 返回 `exists`，不因重投自动替换正文 | 去重是独立规则，不与审核排除条件混用 |
| 用户明确拒绝收录 | 才删除条目、原文和独占附件，并记录禁止再次收录的来源指纹；再次命中为 `discarded` | 本轮不执行拒绝、删除或清理，也不把模型否决解释为用户删除 |
| 接收成功 | `accepted` 表示已接收并进入后续任务；长文可能仍在分段审核 | 接收成功不等于审核、处理与索引已经全部完成 |

需要区分：空正文会在接口层被拒绝；可读但只有口号的正文，才属于内容审核问题。缺链接在当前程序中通常是待审原因，不是“已经删除”。

## 3. 三类处理标准：供本轮讨论的建议

本节 △ 均未定案，不写入 `CONTEXT.md` 或 ADR，也不替代尚未完成的保存内容和处理职责问题单。

| 项目 | 资讯 | 参考资料 | 人工笔记 |
| --- | --- | --- | --- |
| 内容审核执行 | △ 按已确认的两条排除标准做模型审核，不额外要求机构发布或个人署名 | △ 按已确认的两条排除标准做模型审核，不额外要求全文或链接 | △ 只做技术校验，不调用模型判断笔记是否“值得保存” |
| 正文 | △ 保留本次提交内容，不猜测或补写缺失信息；摘要与全文如何分别保存另议 | △ 同左 | ✓ 原稿完整保留；△ 默认不调用模型处理原稿 |
| 标题与摘要 | △ 缺标题时补全；自动产生一句概述、3–5 条重点和关键词，保留时间、条件及观点归属 | △ 缺标题时补全；自动提炼用途、主要特点、适用条件及已有研究线索，不杜撰架构 | ✓ 摘要可选；△ 默认不生成，需要时再明确生成 |
| 分类与主题 | △ 使用库内内容类型及已有主题；不确定的分类归“其他” | △ 同左 | △ 手工或按需整理，不作为保存的前置条件 |
| 实体与关系图谱 | △ 保留 main 的可用机制：重点实体抽取、候选事实核查，关系按内容类型配置开启；不从共现推断关系 | △ 沿用 main：默认不抽实体、简介及关系 | △ 沿用 main：默认不抽实体、简介及关系 |
| 检索 | △ 正文及可用图片建立索引；不以缺图阻止保存 | △ 同左 | △ 直接为原稿建立索引，摘要不是索引前提 |
| 处理失败 | △ 保留已提交内容与错误，允许重试，不伪装成已完成 | △ 同左 | △ 可选摘要失败不应使已保存的笔记变成拒收 |
| 对外部 Agent 的职责 | △ 提交已有内容与已知来源，不要求它先自动补齐全文 | △ 后续研究由 Web Agent 按使用需要执行；分析报告与来源原文区分 | △ 不由采集任务或模型覆盖本人的原稿 |

这些是处理行为建议，不是要求每份资料具备所有字段。资讯和参考资料原有“精简内容为主、全文按需”的保存形态仍是建议，未在本轮改为最终规则。

## 4. main 当前还有哪些策略

### 4.1 库删除后留下什么

| 层次 | main 当前源码 | 删除库的影响 |
| --- | --- | --- |
| 库实例 | 允许零库；用户从模板自行新建；只有空库可删除，软删除资料也计入非空判断 | 删除该库及库专属配置 |
| 模板规则 | 四种：外部时效型、外部长效型、自有型、生成型；决定来源要求、去重、审核和处理机制 | 保留在源码，不随删库删除 |
| 默认审核文字 | 官方、媒体、参考、个人、AI 产出共五份建议标准 | 保留在源码，新建时按模板选择；用户保存的自定义标准优先 |
| 每库配置 | 审核文字、来源规则、模型、内容类型、关系类型、分块及关注动态等 | 被删除库的配置不再有效，也不由新库自动继承 |
| 运行实例状态 | 本次只查源码，未查询运行数据库 | 不能据此断言现在部署中一定为零库，或某个旧策略仍绑定在运行库上 |

三类是用途，不等于 main 已经改成三种模板。当前可作近似映射：资讯→外部时效型，参考资料→外部长效型，人工笔记→自有型。第四种生成型仍用于 AI 产出，不审核、不调用模型处理，只建索引；本轮不决定删除或合并它。

### 4.2 main 三类近似映射的现有行为

| 项目 | 资讯：外部时效型 | 参考：外部长效型 | 人工笔记：自有型 |
| --- | --- | --- | --- |
| 程序来源要求 | 新库默认必须有链接；可按库改为链接或机构加发布日期，后者标来源未核实 | 链接或 `identifier` 至少一个 | 不要求外部来源；`source_ref` 可选 |
| 默认模型审核 | 新库默认官方标准：发布者须可识别为机构，有具体事实、变化、安排、结果或机构主张；排除空泛导流、招聘为主、无新增信息的纯转发。旧媒体角色另有报道、观点和实践标准 | 允许文档、章节、摘要、摘录、步骤、代码和有说明的资源索引；排除空白、占位、无信息导航和无法辨认参考信息的内容 | 仍调用模型审核：可读且有实际信息或记录事项；允许草稿、SOP、清单及未完成记录，排除空白、纯占位和无可辨认信息的乱码碎片 |
| 完整度要求 | 不因短、缺全文、图片或上下文而拒绝；限制写审核说明 | 不要求独立运行、复现或完整论文、教程 | 不要求成稿、最终结论或公开发表质量 |
| 默认处理 | 补缺失标题，生成摘要、内容类型和主题 | 同左，按参考资料提炼 | 同左，摘要当前仍是自动处理的一部分 |
| 实体和图谱 | 抽重点实体；关系由内容类型与图谱配置控制，再核查原文证据 | 不抽实体、简介和关系，传 `graph: true` 也不启用 | 同参考 |
| 正文与检索 | 保存提交正文，不补写缺失内容；建立文本、图片索引；不生成新的逐图说明或缺图待办 | 同左；固定采用父子分块 | 同资讯 |
| 去重 | 同库 URL、正文指纹及部分近似匹配；可归并转载来源、折叠相似报道 | 同库 URL、文献标识、正文指纹；不做上述近似归并 | 有 `source_ref` 时比较同来源最新正文，变化则新增记录保留旧记录；无标识时可按正文指纹判重 |
| 显式正文更新 | 按条目 ID 替换完整正文，保留 ID 与来源，撤除旧派生数据后重新审核、处理；不保留被替换正文版本 | 同左 | 同左；与 `source_ref` 变化后另存记录是两条不同路径 |

**重建资讯库时有一个具体差别：** 现在新建 `external_timely` 库，默认是官方审核标准加 `link_required`。仅把新库命名为“资讯”或“媒体信息”，不会自动得到旧媒体角色的标准或全部处理分支，也不会复制旧库的模型、内容类型、关系类型及动态配置。

### 4.3 与已确认需求及待审草案的差距

1. 三类需求不追加来源门槛；main 的两种外部模板仍有程序来源门槛，不能只改审核提示词解决。
2. 人工笔记只排除空内容和技术异常、摘要可选；main 仍做模型审核和自动摘要。是否改为第 3 节建议，待用户确认。
3. 资讯需求包含新鲜消息；main 新库默认官方发布者标准，不能直接当作已经统一的资讯标准。
4. 原去重草案不做语义归并、允许无 URL 独立新建；main 仍有正文指纹去重，资讯还有近似匹配和转载归并。
5. 原补充草案提出摘要与全文分别保存、保留一版历史；main 的显式正文更新是完整替换且不留旧正文版本。草案尚未获确认，不直接据此实施版本系统。

## 5. 去重与补充：保留的未确认草案

本节保留上一版讨论，不因本轮展示而定案。资讯和参考资料建议共用机制，但分别在本库执行。

| 情况 | 人工笔记库 | 资讯库／参考资料库，各自在本库内 |
| --- | --- | --- |
| 定位原记录 | △ 按条目 ID；引用 URL 不用于合并笔记 | △ 明确条目 ID 优先，否则按 URL 定位，再比内容指纹 |
| 完全重复 | △ 新建笔记不因文字相同被合并；同条编辑未变则不改动 | △ 已定位同条资料且指纹相同：跳过重复保存 |
| 没有 URL | △ 新建或按条目 ID 编辑 | △ 正常新建，允许重复；以后按条目 ID 补充 |
| 同主题、同事件、不同 URL | △ 分别保存 | △ 分别保存，不做语义去重或自动归并 |
| 摘要后补全文 | △ 本人明确编辑 | △ 同库沿用原条目，保留摘要并加入明确提交的全文 |
| 已有全文又收到摘要／片段 | △ 本人明确编辑 | △ 保留全文，新内容作为补充 |
| 内容变化但未说明替换 | △ 自动采集不改写原稿 | △ 附为补充，不覆盖或自动重写正文 |
| 明确替换正文 | △ 本人明确编辑；历史版本未定 | △ 替换来源正文，保留上一版；此建议与 main 不同 |

## 6. 本轮待确认与后续依赖

本轮讨论处理默认值，不重新询问已经确认的两条排除标准：

1. 人工笔记是否采用“技术校验后保存并索引，不做模型价值审核，摘要按需”的建议。
2. 资讯是否默认自动摘要、分类与主题，并保留按内容类型控制的图谱机制。
3. 参考资料是否默认自动摘要、分类与主题、建立检索索引，不抽图谱。

上述三项尚未回答。后续仍按原地图确认保存形态（02）、处理职责（03）、去重与补充（05）及库与模板边界（06）。本表不是实现任务单，不把三类用途或处理建议写成当前领域事实；暂不新增 ADR。
